# 如何准备外贸 Facebook 社区筛选、内容与询盘流程

本文保留社区筛选、内容准备和询盘承接流程，供外贸运营与研发评审。依据来自[Meta 规则与外贸材料研究](../reports/facebook-community-research-20261021.md)；2026-10-21 按项目方要求，暂缓依赖该 Facebook 账号的 Playwright 开发。下文的自动化契约与测试矩阵仅保留为设计参考，不构成当前开发排期。

## 当前保留范围与暂停条件

社区筛选标准、群规检查清单、自有内容草稿和询盘字段设计可以继续准备。需要该账号登录、读取真实群、校准选择器、提交互动或验收的工作全部暂缓，不因账号恢复或经过若干天自动重启。

当前安排如下：

- **保留**：行业与市场筛选方法、内容来源与审核要求、主动入站询盘的整理和人工报价交接流程
- **暂缓**：依赖该账号的 Playwright 适配、开发、调试和真实验收，以及以此为前提的任务
- **设计参考**：独立合成测试与契约草案保留，本次不启动实现
- **恢复条件**：项目方明确恢复开发，再核对账号可用性、授权范围与 [Decision #623](https://github.com/ban12-project/F-Trade-Platform/issues/623) 的适用权限依据

保留询盘流程不表示当前账号已能接收或处理消息。先准备字段、来源核验和人工交接，账号运行能力仍以实际状态为准；本次不修改现有运行开关。

## 实施计划与未决输入

目标是让实现者据此验证一次社区参与任务的授权、确认、提交和停止行为。先定义运营步骤与动作边界，再定义契约和测试，不以账号活跃度推断执行资格。

计划需要以下输入：

- **受众**：渠道负责人、浏览器节点及应用研发
- **首批目标**：一个人工选定的行业社区；不预填真实群或联系人
- **内容顺序**：筛选与规则、人工参与、草稿审核、执行状态、结果处理
- **未决项**：目标市场、参与身份、群规则版本、平台权限依据与留存策略
- **范围依赖**：[ADR 0002](../decisions/0002-camofox-facebook-personal-profile-mvp1.md) 的既有边界及 #623 的新增范围决策

## 外贸运营步骤与完成条件

下表保留运营流程与完成条件；需要该账号执行的步骤暂缓。所有天数、时长及动作配额都不用于判断账号安全。

| 顺序 | 操作 | 完成条件 | 自动化边界 |
| --- | --- | --- | --- |
| 1 | 确认账号身份、业务介绍和所有者授权 | 身份与使用目的可核对 | 不自动创建身份或伪造生活动态 |
| 2 | 人工搜索行业社区 | 记录候选地址、语言及品类相关性 | 示例搜索词：`clutch aftermarket`、`auto parts importer`、`automotive distributors`；不自动遍历成员 |
| 3 | 检查群规和近期讨论 | 明确广告、链接、联系方式、审批及参与身份限制 | 未取得规则时停止；不以人数推断采购价值 |
| 4 | 人工决定加入或参与 | 如实回答入群问题；确认成员/参与审批状态 | 不自动回答验证问题或批量申请 |
| 5 | 选择一个相关问题，准备回答或帖子 | 保存目标引用与自有草稿，不归档成员资料 | 不随机点赞、关注或刷评论 |
| 6 | 审核事实与具体动作 | 内容真实性审核（Gate 01）通过；确认准确身份、目标、正文及附件版本 | 任何修改使确认失效；不生成 OE、尺寸、认证或性能事实 |
| 7 | 执行一次获准的动作 | 权限、页面、身份与确认均有效 | 当前真实群内执行尚待 #623；结果不明即暂停 |
| 8 | 承接对方主动发起的私信 | 在业务库中按现有权限处理询盘 | 不主动群发；正式价格与交期继续人工确认 |

## Playwright 拟议能力与默认开关

以下是恢复开发后的候选设计，当前不启动本地合成场景或账号适配。即使是只读线上观察，也须先核对平台权限，不能以“没有发帖”作为许可依据。

| 能力 | 本地合成测试 | 真实社区默认值 |
| --- | --- | --- |
| 检查群规版本、身份、目标和审批 | 拟验证 | 关闭，等待权限与页面核验 |
| 编辑、预览及确认自有草稿 | 拟验证 | 可在本应用处理；不因此访问 Facebook |
| 群内发帖或评论 | 模拟一次提交及回执 | 关闭，等待 #623 和对应验收 |
| 加群、好友请求、点赞与关注 | 验证拒绝执行 | 关闭，不纳入本阶段实现 |
| 成员列表采集、陌生人私信、互动配额 | 验证拒绝执行 | 关闭，不纳入本阶段实现 |

优先复用现有驱动的授权和熔断机制。先检查浏览器节点传输适配是否支持所需动作，再实现页面适配；测试使用 Playwright 不等于要替换现有浏览器运行时。

## 拟议结构化契约

通过结构化命令传递任务，不把自然语言研究摘要直接交给执行器。以下字段仅为评审草案；实施时须补 Zod schema、服务端授权及版本迁移。

| 对象 | 必需字段 | 拒绝条件 |
| --- | --- | --- |
| `CommunityScope` | `version`、`accountRef`、`channelRef`、`groupRef`、`identityRef`、`allowedActions`、`platformPermissionRef`、`rulesEvidenceRef`、`rulesVersion`、`reviewedAt`、`expiresAt` | 权限或规则证据缺失、过期、身份不符、目标超范围 |
| `ParticipationCommand` | `commandId`、`scopeRef`、`scopeVersion`、`action`、`targetRef`、`draftRef`、`draftVersion`、`contentHash`、`approvalRef`、`approvedBy`、`approvalExpiresAt`、`idempotencyKey` | 未获准动作、审核撤销、正文或附件变更、确认过期、重放 |
| `ParticipationReceipt` | `commandId`、`outcome`、`reasonCode`、`observedAt`、`externalRef`（可空） | 不得因按钮消失或超时推断发布成功 |

服务端在每次执行前重新认证所有者、授权目标和校验输入。确认须绑定正文与附件清单的哈希、身份、目标、动作和版本；不得将浏览器截图视为授权凭证。

## 状态、回执与停止条件

状态反映可验证的执行结果。管理员待审批、实际可见与未知结果必须分开处理。

顺序及异常出口如下：

1. `draft`：生成自有草稿，尚未获准执行。
2. `awaiting_approval`：等待人工确认绑定的具体内容与目标。
3. `ready`：执行前重新校验身份、范围、规则版本及审批。
4. `executing`：同一账号租约内只允许一次提交。
5. `pending_moderation`：页面明确显示待管理员审批；不当作已发布，也不重新提交。
6. `confirmed`：明确观察到与命令匹配的外部回执；是否对他人可见仍以平台实际状态为准。
7. `unknown`：提交后超时、断连或回执无法确定；暂停写入并人工核实，不自动重试。
8. `blocked`：权限不足、群规变更、身份不符、检查点、验证码、账号限制或页面不匹配；停止后续任务。

`unknown` 与 `blocked` 不按时间自动恢复。提交前可对无副作用的本地检查重试；提交后只允许另行获准的结果核查，不重新点击提交。平台回执不能保证 exactly-once，也不表示对方愿意接受私信。

## 本地验收矩阵与数据限制

用虚构身份、群规和帖子搭建本地页面，拦截外网请求。测试只验证实现行为，不能证明真实 Facebook 选择器、账号安全或平台许可。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 单条审核通过的合成评论 | 一次提交；命令与回执一致 |
| 缺少平台权限、规则或审批 | 提交次数为零 |
| 草稿、附件、目标或身份变更 | 旧确认失效；提交次数为零 |
| 重复命令、并发执行或租约丢失 | 不重复提交；租约无效后停止 |
| 管理员审批中 | `pending_moderation`；不报告成功、不重发 |
| 提交后断网或无可识别回执 | `unknown`；不自动重试 |
| 验证码、限制提示或页面结构变化 | `blocked`；不尝试绕过 |
| 点赞、好友请求、名单采集或主动私信命令 | 拒绝执行 |
| 授权撤销、确认过期或版本过期 | 执行前拒绝；不沿用旧权限 |

GitHub 只保存合成 fixture、规则与测试结果。真实群名单、帖子正文、联系人及互动流水只进入经授权的业务存储；凭据、Cookie、截图和 trace 不进入 Git 或 Issue。真实试点前明确留存期限、删除流程和访问角色，未决时不采集。

## 实现交付与线上试点的区分

[任务 #624](https://github.com/ban12-project/F-Trade-Platform/issues/624) 按项目方决定以“没有计划”关闭，自动化设计仅作参考；如需恢复，另行明确范围并创建研发任务。线上启用需要 #623 的明确结论、适用平台权限依据、当前群规、已审核页面配置及单社区验收；任何缺项都保持新增功能关闭。

本规格不修改现有 Product、Content、RFQ、Quotation 或 Workflow 契约。后续实现若扩展这些契约，须同步 schema、fixture、迁移和人工确认流程。
