# 工作台目录批量导入

Issue #340，父项 #268 / #26。本文描述待实现的契约，不能作为功能交付或验收证据。

现有页面把整份资料交给单产品抽取；CLI 才有目录候选发现与逐条抽取。
工作台必须让用户上传目录、查看独立候选、选择最多 20 条记录，并逐条生成待审草稿。
重复编号保留不同记录，任何结果都不自动变成 Product Ready。

## 持久化与执行

1. 上传继续使用项目绑定的私有文档回执。创建目录任务的 Action 重新验证身份、角色、
   活动营销项目和回执所有权；目录任务与回执一对一，重复提交返回同一任务。
2. 文档解析在 durable workflow 的 step 中执行，不占用整个浏览器请求。以私有原件
   的服务端路径读取和核验摘要；沿用现有 PDF/OCR 解析与候选发现。状态为等待解析、
   解析中、可选记录或解析失败。解析失败须能重试，不能吞掉原始失败。
3. 服务端保存不可变的解析来源、原件证据 ID 和各候选来源。候选用独立 UUID 标识，
   编号不是主键；每条保留物理页、记录位置与重复编号复核标记。
4. 选择 Action 只接受目录任务 ID、候选 UUID 集合和已保存的模型配置/模型名。
   服务端校验所选记录归属、唯一性、数量上限与可运行状态，拒绝客户端来源正文或事实。
5. 每条抽取为独立 workflow step，沿用 EvidenceLocatedProductAgent、字段来源验证和
   现有草稿入库事务。每次尝试有独立 token 与租约；旧 worker 的迟到结果不能覆盖重试。
   完成项再次提交不再调用模型或创建草稿。失败项可单独重试，成功项和失败历史均保留。
6. 长任务读取来源前与最终写入时重新校验会话、角色、项目编辑权限及活动状态。
   完成记录与草稿/审批/事件/项目关联在同一事务写入；草稿保持 `PRODUCT_REVIEW_REQUIRED`。

客户端只接收任务状态、候选摘要、物理页位置、错误类别和已创建草稿链接。
不接收原始数据库行、私有路径、模型凭据或整份解析正文。页面可刷新恢复进度，
通过有界轮询读取状态，不把 React 状态当持久任务队列。

## 界面

沿用现有 shadcn Card、Field、Input、Checkbox、Table、Badge 与 Alert。
目录入口与单产品粘贴入口明确区分。用户先上传、等待解析，再选择候选和模型；
显示选中数量与独立重复记录，批量生成后逐行展示等待、处理中、失败或待审核草稿。
不得把候选识别数称为准确率，不得把 OCR 或版式恢复后的字段称为已确认事实。

## 验收证据

- 纯合成浏览器测试从文件上传开始，完成候选选择、20 条独立待审草稿及数据库回读。
- 重复编号保留独立来源；非法候选、超过 20 条、重复 UUID 与错项目请求被拒绝。
- 模型部分失败与重试不重复创建成功项；并发提交、租约过期和迟到结果有回归。
- 会话失效、权限撤销、项目归档后不能读取来源或写入草稿。
- 来源摘要、物理页与字段证据可追溯到本次私有原件；没有自动批准或工程事实补造。
- 实际参考文件/模型运行另作受控验收，缺失字段可按已有授权使用独立 MOCK 来源补充；
  模拟审批、内容、询盘与商机结果不能冒充真实工厂审批或渠道投递。
