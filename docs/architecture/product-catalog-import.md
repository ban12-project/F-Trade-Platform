# 工作台目录批量导入

Issue #340，父项 #268 / #26。目录批量导入已完成本机浏览器、数据库回归及实际模型验证；
生产部署与完整 MVP 验收尚未完成。详细证据见 [验收记录](../testing/product-catalog-import.md)。

实施前，页面只能把整份资料交给单产品抽取，目录候选发现与逐条抽取依赖 CLI。
当前工作台支持上传目录、查看独立候选、选择最多 20 条记录，并逐条生成待审草稿。
重复编号保留不同记录，任何结果都不自动变成 Product Ready。

## 持久化与执行

1. 上传继续使用项目绑定的私有文档回执。创建目录任务的 Action 重新验证身份、角色、
   活动营销项目和回执所有权；目录任务与回执一对一，重复提交返回同一任务。
2. 文档解析在 durable workflow 的 step 中执行，不占用整个浏览器请求。以私有原件
   的服务端路径读取和核验摘要；沿用现有 PDF/OCR 解析与候选发现。状态为等待解析、
   解析中、可选记录或解析失败。解析失败须能重试，不能吞掉原始失败。
3. 服务端保存不可变的解析来源、原件证据 ID 和各候选来源。候选用独立 UUID 标识，
   编号不是主键；每条保留物理页、记录位置与重复编号复核标记。
4. 选择 Action 只接受目录任务 ID、候选 UUID 集合和已保存的模型配置/模型名。
   服务端校验所选记录归属、唯一性、数量上限与可运行状态，拒绝客户端来源正文或事实。
5. 每条抽取为独立 workflow step，沿用 EvidenceLocatedProductAgent、字段来源验证和
   现有草稿入库事务。每次尝试有独立 token 与租约；旧 worker 的迟到结果不能覆盖重试。
   完成项再次提交不再调用模型或创建草稿。失败项可单独重试，成功项和失败历史均保留。
6. 已提交的目录解析可跨登录会话继续。领取原件及写入候选时，分别在事务内复核发起人的产品写入权限、营销项目活动状态和项目编辑权限。授权仅覆盖本次有效尝试及其原件；生成产品草稿须另行选择候选与模型，逐条抽取仍校验提交会话。
   完成记录与草稿/审批/事件/项目关联在同一事务写入；草稿保持 `PRODUCT_REVIEW_REQUIRED`。

客户端只接收任务状态、候选摘要、物理页位置、错误类别和已创建草稿链接。
不接收原始数据库行、私有路径、模型凭据或整份解析正文。页面可刷新恢复进度，
通过有界轮询读取状态，不把 React 状态当持久任务队列。

## 界面

沿用现有 shadcn Card、Field、Input、Checkbox、Table、Badge 与 Alert。
目录入口与单产品粘贴入口明确区分。用户先上传、等待解析，再选择候选和模型；
显示选中数量与独立重复记录，批量生成后逐行展示等待、处理中、失败或待审核草稿。
不得把候选识别数称为准确率，不得把 OCR 或版式恢复后的字段称为已确认事实。

### 上传与恢复边界（2026-11-14）

选择文件不自动上传。上传阶段可以停止并保留文件选择重试；迟到响应不能继续创建目录任务，
但停止不删除已被服务端接收的文件。创建目录任务的请求发出后，停止上传入口关闭，
关闭页面也不代表后台任务已取消，见 [#1026](https://github.com/ban12-project/F-Trade-Platform/pull/1026)。

若创建请求的响应丢失，页面不能断言上传或任务创建失败。此时先读取已有任务，
读取成功前禁止再次上传；读取操作不会自动重发创建请求。成功读取为空也不是对未来状态的保证，
见 [#1032](https://github.com/ban12-project/F-Trade-Platform/pull/1032)。

进度读取失败时保留上次数据并标明可能过时；成功刷新只清除读取提示，不清除未解决的提交错误。
人工操作期间暂停轮询，结束后按原频率恢复，任务结束后停止。候选状态更新后，
仅从选择中移除当前不可生成的记录并提示数量，保留其他选择与模型设置；服务端仍独立校验。
相关实现与合成浏览器证据见 [#1034](https://github.com/ban12-project/F-Trade-Platform/pull/1034)、
[#1036](https://github.com/ban12-project/F-Trade-Platform/pull/1036) 和
[#1038](https://github.com/ban12-project/F-Trade-Platform/pull/1038)。这些合并记录不证明已部署到生产。


## 验收证据

- 合成浏览器测试验证上传、选择、状态恢复和失败重试；独立 PostgreSQL 回归验证 20 条草稿事务写入。
- 重复编号保留独立来源；非法候选、超过 20 条、重复 UUID 与错项目请求被拒绝。
- 模型部分失败与重试不重复创建成功项；并发提交、租约过期和迟到结果有回归。
- 权限撤销或项目归档后，解析任务不能再领取原件或提交候选；已提交的候选保留。单独选择的草稿抽取还要求原会话有效。
- 来源摘要、物理页与字段证据可追溯到本次私有原件；没有自动批准或工程事实补造。
- 实际参考文件/模型运行另作受控验收，缺失字段可按已有授权使用独立 MOCK 来源补充；
  模拟审批、内容、询盘与商机结果不能冒充真实工厂审批或渠道投递。

## 当前实现与验证

- `lib/db/product-catalog-schema.ts` 与迁移 `0040` 保存目录、候选和尝试历史。
- `lib/product/catalog-import-store.ts` 提供权限、并发领取、租约及事务写入边界。
- `workflows/product-catalog-import.ts` 每批最多并行两条；Action 位于
  `lib/actions/product-catalog.ts`，页面位于 `components/workspace/product-catalog-import.tsx`。
- `scripts/test-catalog-import-contracts.ts` 验证客户端提交契约。
- `scripts/test-catalog-import-postgres.ts` 在允许列表中的本机测试库验证 20 条独立待审草稿、
  重复编号/页码、并发领取、部分失败重试、过期任务隔离、会话/账号/项目成员权限撤销、
  归档项目拒绝以及无来源事实拒绝。使用合成 Blob 适配器与合成模型结果，不调用实际模型。
  清理仅针对本次合成记录；在同一事务临时禁用审计删除保护并恢复，失败则回滚。
- TypeScript、Turbopack 生产构建、合成浏览器回归与 Next.js 运行时错误检查通过。
- 实际参考 PDF 经浏览器私有上传、32 页 OCR 与候选选择，保存 20 条独立待审草稿。
  每条仅有来源支持的编号，必需字段仍缺失；这不构成完整抽取准确率或 Product Ready 证据。
- 无效模型输出只在原总时限内纠正一次，不放宽验证器。模型遗漏编号时，只能从对应
  有明确标签的来源片段逐字保留编号，并在审计记录区分；不补造其他产品字段。
- 临时云原件已删除，并以禁用缓存的私有读取确认不存在。本机隔离草稿保留用于后续测试。
