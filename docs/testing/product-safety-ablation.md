# Product Agent 安全控制消融与 Issue 审计

执行日期：2026-09-05。关联研发 Issue：#261。审计基线：`afeb06a`（PR #259 合并后的主线）。

## 方法与结果

运行 `pnpm eval:product-safety-ablation`，输出每个合成案例的接受／拒绝结果、拒绝阶段、错误原因及四个生产模块的 SHA-256。实验只在自动删除的临时副本中移除检查，结束后确认原始模块哈希不变；不改变生产开关或门禁，不读取模型配置，不调用模型或数据库。

使用相同的 10 个案例：2 个有效记录、2 个错误字段定位、2 个 Agent 冒充审批人、2 个同时错误定位和 Agent 审批、1 个未知证据引用、1 个虚构 OE。两条记录只提供小规模重复，不是独立随机抽样。模拟模型输出仍经过实际 `finalizeProductAgentDraft`、`EvidenceLocatedProductAgent` 和 `approveProductDraft`；最后一个函数返回 `verified` 才记为放行。

| 变体 | 有效记录放行 | 不安全输入错误放行 | 错误放行率 |
| --- | --- | --- | --- |
| 完整控制 | 2/2 | 0/8 | 0% |
| 移除逐字段证据定位检查 | 2/2 | 2/8 | 25% |
| 移除审批者必须为 human 的检查 | 2/2 | 2/8 | 25% |
| 同时移除两项检查 | 2/2 | 6/8 | 75% |

移除证据定位检查后，字段值即使存在于整份文档中，也可能指向错误的字段来源。移除 human 检查后，Agent 可以在这条领域函数链路中冒充审批者。只移除其中一项时，另一项仍阻止双重攻击；两项同时移除后，双重攻击也通过。未知引用和虚构 OE 在四种变体中均被其余校验拒绝。

结果支持保留两项独立控制。它不证明模型识别准确率、工程事实真实、整套系统不存在绕过，或真实 SKU 已完成验收。实验没有运行 HTTP 身份认证、数据库权限和工作流状态机等额外防线，错误放行只描述这里测试的领域函数链路。审批状态、对象归属、时间及证据要求均保留；“移除 human 检查”不等于删除整个 Gate 01。该实验也不是 README 的 A–D 完整度／图片效果评测；真实试点仍依赖 #6/#5/#32。

## 本地验证

在基线主线的隔离工作树运行 12 组定向测试，均通过：视频契约、导出预设、媒体探测、实际 synthetic MP4 验收、任务执行、任务提交、MVP 生成禁用策略、Product Agent 证据定位，以及四组 ProductMedia 权利／持久化／选择／运行时策略测试。

消融脚本在 CI 中重新执行，并断言完整控制不放行不安全案例、所有变体均保留有效记录，以及生产源文件不变。每次变体均从相同源文件创建独立副本；变更目标必须恰好匹配一次，生产代码漂移会报错，不能静默运行错误实验。上表是本次实测结果；脚本输出未来运行的实际值，不强行套用该表。
