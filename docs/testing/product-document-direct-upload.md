# 产品文档私有直传验收

2026-09-15，Issue #338。测试使用隔离本地 PostgreSQL、合成账号和合成 CSV，Blob 为已关联开发存储。没有运行产品模型、文档 Sandbox 或真实社媒操作。

## 修改与边界

- 证据库、Product Agent Action 和流式导入统一使用项目绑定的私有上传回执。文件字节不经过 Server Action 或流式导入请求。
- 签名验证登录、产品写权限、活动营销项目和成员编辑权限；回执绑定所有者、项目、用途、路径、文件名、类型、大小及 15 分钟有效期，不重复签发。
- 领取时按服务端保存的路径读取私有文件，边读边检查大小，检查文档签名或 CSV UTF-8 文本，计算 SHA-256。文件签名校验不是内容事实审核，也不代替后续解析。
- 最终事务锁定项目并重新授权，原件证据、项目关联和回执领取原子写入。并发领取返回同一证据；相同字节的另一次上传保留独立来源。用途不同的回执不能互用。
- 证据库保存不再执行文档解析；只有 Product Agent 导入会解析已领取原件，沿用现有按需解析及清理行为。

## 复现

数据库回归已加入 `repository-validate` CI。设置指向本机专用测试库的 `DOCUMENT_UPLOAD_TEST_DATABASE_URL`，运行：

```sh
node --conditions=react-server --import tsx scripts/test-document-upload-postgres.ts
```

真实 Blob 浏览器回归为显式运行的测试，需要已迁移的 `f_trade_browser_test` 本地库，以及连接同一合成库的运行中应用。设置 `DOCUMENT_UPLOAD_BROWSER_URL`、`DOCUMENT_UPLOAD_TEST_DATABASE_URL`、`DOCUMENT_UPLOAD_TEST_AUTH_SECRET`，从受控环境载入开发 Blob 凭据后运行：

```sh
node --import tsx scripts/test-document-upload-browser.ts
```

该脚本新建合成用户、会话和项目，完成后删除自身创建的云文件及数据库记录，只输出聚合结果。不得把凭据、原件或私有链接加入报告。

迁移 0039 只新增文档回执表。生成器最初重复输出 0029、0030、0038 已有的运行表、确认字段和索引；逐条核对后从新迁移去除了重复语句，保留历史迁移不变，空库升级已验证。

这些结果证明本地应用经真实 Blob 的浏览器上传与回读，不代表生产部署、参考原件导入、Product Agent 大文档解析或 MVP1 最终验收全部通过。
