# CSV 产品导入表头与零字段结果

产品导入只接受能由原始资料及字段证据验证的值。模型输出不是工程事实来源。

基础 CSV 表头可使用 `Product name`、`Product type`、`Internal SKU`、`OE`、
`Application`、`Vehicle brand`、`Vehicle model`。保持来源值原样，不要为了通过
校验改写 OE 或车型。`product_name`、`oe_numbers` 等机器字段名不是这些表头的别名；
通用 `Model` 不能作为车辆型号证据。缺少资料的字段应留空并补充来源。

流式导入结束时，若没有任何字段通过来源校验并成功保存，运行记为失败，界面显示
“未提取到可由来源验证的字段”及表头检查提示。零字段也可能来自空模型输出或不合格
字段证据；该提示不意味着系统已确定唯一原因是 CSV 表头。

开始导入时创建的空草稿保留用于核查，仍受产品审核门禁约束。本次修复不修改历史
空草稿，不扩展工程字段别名，也不自动批准产品。已有至少一个合格字段的导入保留
原有待审核完成行为；未通过的字段仍需补证。

回归覆盖 `scripts/test-product-stream.ts` 的空输出、机器表头、歧义车型标签及
支持标签的精确名称/OE 保存，并由 `tests/e2e/project-workflow.spec.ts` 检查浏览器
显示失败提示和保留草稿链接。浏览器测试使用合成上传及流响应，不代表真实模型验收。

2026-09-18 本地验证：类型检查通过；上述两个浏览器场景在 Next.js 16.3.2
Turbopack 开发服务通过，Next.js 运行错误列表为空。首次用 `127.0.0.1` 访问默认
`localhost` 开发服务时，开发资源受来源限制、页面未完成 React 初始化，两场景失败；
改用服务声明的 `localhost` 后通过，未扩大超时或移除断言。Google Fonts 下载失败
时开发服务使用回退字体；这不是产品导入失败。
