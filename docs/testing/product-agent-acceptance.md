# Product Agent 验收矩阵

本矩阵按 [ADR 0010](../decisions/0010-product-final-fact-acceptance.md) 与 `config/product-acceptance.yaml` v2.0.0 执行，保留 20 个不同试点产品、A–D 各五个的范围。**自动识别用于节省审核时间，最终事实审核决定产品就绪。**

`docs/reference/` 已获[真实来源及素材用途授权](../reference/README.md#当前真实来源与素材用途授权2026-10-08)，可按原件支持的事实开展真实 SKU 审查。本次 Agent 委托审核如实记录执行者和授权；授权不能补足原件未提供的工程事实。此前 test-only、MOCK 和合成运行继续保持原分类。

## 单产品判定

产品仅在下列条件同时成立时成为 ProductReady：

1. 当前关键身份字段完整：产品名称、类型、内部 SKU，以及自身 OE 或完整且确认的品牌、车型和应用；`blocking_missing_fields` 为空。
2. 每个已填写事实都有属于当前产品和项目的字段级来源证据，最终值经对照原件核实。工程单位、整件规格和适配不能从部件栏、邻行、常识或营销语言推断。
3. 当前产品版本取得有效 Gate 01 事实审核批准；图片一致性仍按现有图片审核要求确认。不得用旧版本批准或自动抽取成功代替批准。
4. 人工补录和纠正保留改前、改后值、字段路径、两侧证据引用、来源引用、版本、执行者、时间和随后送审的记录。修改后的字段必须重新选择已上传证据，再次送审。

允许自动识别漏读、误读。对照原件能够确认的字段可人工补录或纠正；无法确认的字段继续缺失，不能以置信度或平均识别率放行。原件没有给出尺寸单位时，不能把目录元组填入带 `mm` 的整件规格字段。

产品修订与修改记录在同一数据库事务保存；私有 `audit_event` 的 `product_draft_revised` 记录保存字段差异，并由数据库禁止覆盖或删除。未改动字段可保留原有定位证据；变更值或来源不能复用旧定位冒充重新核实。旧修订记录只有数量时，不回填虚构的历史差异。

手动录入或修订也可附带原始产品图片，经已有私有上传核验后与草稿同事务保存，追加图片仍需重新送审。每个产品共最多四张，已有图片保留；创建／修订审计记录其引用。图片不能代替文字事实证据，带图批准仍须明确核对图片与当前产品一致。

## 效率与安全分别报告

自动抽取阶段的字段逐字匹配率、OE 保留率、车型原值匹配率、阻断缺失召回率，以及审核耗时和修订轮次均为诊断或效率指标，不设产品就绪阈值。自动误读不等于最终事实允许误读；最终已填写事实必须有来源且审核通过。

OE、车型、品牌及应用的自动抽取仍使用严格来源校验，允许去除首尾空白，不改大小写、内部空格和标点，不借用邻行。人工纠正通过独立证据录入并重新送审，不绕过自动抽取校验。标签映射维护在 `lib/product/source-labels.ts`；通用 `Model` 不自动当作车型，部件栏不能自动当作整品事实。

## 执行与版本

1. 为 20 个不同获授权 SKU 绑定槽位，按 A–D 的资料完整性和图片可用性准备输入，运行前固定来源、期望事实、缺失字段、预期结果及证据。
2. 每次新运行指定唯一 `run_id` 和新输出路径，保存自动指标、人工修订轮次、修改审计引用与最终审核记录；新结果必须显式填写 `policy_version: 2.0.0`。
3. 最终审核记录绑定产品版本、审核人、时间、来源清单、证据、关键字段完整性、缺失字段及批准结果。记录只是可检查的声明，真实验收还须回查私有来源、审计和应用状态。
4. 来源期望录入错误可建立有原件、旧值、新值、理由和审核者的版本化勘误。保留原期望和原运行结果，后续运行引用新的来源清单，不能事后改旧成绩。
5. 失败记录引用对应原研发 Issue；本次用户允许同一 Issue 补充 PR。GitHub 只保存脱敏缺陷与交付证据，真实 SKU 事实、原件和修改值保存在私有业务存储。

未带版本的历史结果继续按 v1 的 100% 自动识别和最多一轮修订规则验证；不将旧失败改记为新标准通过。目录 CLI 的新批次必须使用未占用的 `--output` 路径。

## 批次判定

20 个槽位均须完成来源核对和最终处置核查。预期就绪样本必须关键字段完整、有来源、Gate 01 批准并实际 ProductReady；预期缺失关键事实的样本必须正确阻断，记录缺失事实和复核依据。正确阻断可以通过该负例的流程验收，**该产品仍不就绪**。

分别报告“最终就绪数”“正确阻断数”“未执行或处置错误数”和自动识别效率。未执行、最终证据缺失、审核未完成或错误放行都会使批次未通过；识别率低或多轮有记录的修订本身不使批次失败。来源不支持的 C/D 样本不能为了凑齐 20 个 Ready 而补造事实。
