# 受控 Facebook Personal Profile 试运行验收记录

本记录仅保存脱敏研发证据引用；不包含 Cookie、私有截图、聊天正文、代理凭据、业务对象标识或真实客户资料。当前路线为 Vercel Sandbox、原持久 Firefox profile 与固定美国出口 IP，详见 [运行验收手册](../../ops/browser-node/ACCEPTANCE.md)。旧 VPS 描述及“登录和 2FA 一律手动”由当前路线和 [ADR 0002](../decisions/0002-camofox-facebook-personal-profile-mvp1.md) 的 version 2 登录契约替代。

每项能力独立决定 GO / NO_GO。共同前置条件缺失时全部 NO_GO；文本通过不能放行单图、视频、登录恢复或入站。当前页面、因素、身份和受众的审核范围必须有效；保存凭据、显示登录后首页、项目导出预设通过或空收件箱都不能单独证明能力通过。任一硬停止事件必须暂停对应账号／渠道，未知外部效果不得重试。

## Go / No-Go

每项记录能力名称、`GO` / `NO_GO` / `NOT_EXECUTED`、具体范围、决定人／实际执行者、UTC 时间、研发证据引用及未完成条件。用户委托 Agent 执行审核时必须标明，不冒充独立工厂签字。缺失证据或未执行不能计入通过，全部 M2 所需项完成前不能关闭 M2。

失败或未知保留原结果，停止对应执行并继续在原 Issue 补证／修复；可在同一 Issue 补充 PR，不因复测另建 Issue。只有发现不同范围的 Decision / Risk 才新建对应研发 Issue。GitHub 不记录真实业务流水。任何复测都不能重复未知发布／回复效果，也不能靠更改审核日期、移除停止状态或降低事实要求来放行。
