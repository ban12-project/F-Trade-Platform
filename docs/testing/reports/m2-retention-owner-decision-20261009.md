# M2 保留期与责任人委托审核（2026-10-09）

原 Issue：[#122](https://github.com/ban12-project/F-Trade-Platform/issues/122)。实现基线为 main `2d7f5d820b3dbdcb40acef4ee623db6164ba00aa`。

项目方本次明确确认 M2 保留期与负责人问题，并委托 Agent 完成审核。具体天数此前未写入仓库或原 Issue，本次接受 [ADR 0007](../../decisions/0007-marketing-video-release-policy.md) 和[政策 1.0.0](../../../config/marketing-video-release-policy.json)：应用受控的视频工作副本、提示词、处理输出及成片保留 90 天，具名责任账号为 `coda`。天数是本次委托审核选择，不能记成此前已有的业务输入。当前生产设置页面独立显示该账号与管理员角色；原始设置截图和账户详情留在受控本地记录。

审核结论：**业务政策决定通过，运行时保留执行尚未通过。** 此次只新增版本化政策及更新运行手册，不修改身份、权限、数据库、云服务额度、供应商或实际业务内容，也不把 JSON 记录当成运行时已加载配置。现有外部生成仍默认拒绝；本政策明确生成预算为 0，现有剪辑和渲染按获授权服务额度计费。工程事实、素材权利、Gate 01 与独立逐帖确认继续适用。

代码核查发现 `private-asset-store.ts` 读取成片时没有 90 天到期判定，视频聚合和私有 Blob 没有完整到期清理机制；已有临时文件清理和上传回执过期不覆盖此缺口。模型服务、Workflow 回放、日志与备份副本还须逐项核对，不能对供应商作未验证的删除承诺。该执行缺口继续在原 #122 内完成，不另建 Issue，不因此关闭 #122。

运行手册原文仍声称只可使用官方 API 发布且没有运行时媒体探测，与已接受的 ADR 0002 和现有 FFmpeg／ffprobe 实现冲突。本次同步为已批准的受控初始渠道及真实文件测量语义，并保留平台接受 `not_evaluated` 和逐帖确认门禁。

本次验证使用已有 JSON、仓库契约、文档链接及差异检查；没有为静态政策记录新增与内容一一对应的测试。完整交付以本 PR 最终提交的 CI、squash 合并证据为准。本政策记录不需要修改生产环境变量；没有重新发布帖子、删除业务资料、发客户消息或承诺正式报价与交期。M1 全字段覆盖和 20 槽位最终验收继续保持原状态。
