- 依据实际 DOM 审核并保存该账号的空收件箱识别配置；未启用未经审核的历史线程选择器、发布或收件箱采集能力。
- 07:35 UTC 开始的恢复检查中，严格浏览器健康检查通过，运行镜像及获授权代理各字段摘要与选定配置匹配。
- 07:36 UTC 的运行时独立观察为 `state=ready`、`originVerified=true`、`identityVerified=true`、`atReadyUrl=true`、`messengerRestored=true`。已连接远程窗口显示 `/messages/` 和 `No chats`；工作台显示自动完成身份与 Messenger 验证。
- 该运行的 `factorPrompts=[]`，凭据未领取。因此这次成功来自原生会话恢复，不能归因于后台重新提交密码或 TOTP。

私有运行记录、代理摘要、页面元数据和账号绑定留在受控本地验收资料中；本报告不包含账号标识、凭据、Cookie 或消息正文。

## 保留的失败与边界

前一次恢复已展示 Facebook 首页及退出表单，但自动观察返回未验证／拒绝，并未领取凭据。后续成功不证明该间歇性识别失败已修复。本次首页只读统计未超出既有脚本数、文本量、遍历深度与节点限制，不能把早先失败直接归因于解析上限，更不能归因于快照清理。

空收件箱是界面就绪证据，不是历史消息恢复、真实入站、去重或 RFQ 闭环的证据。登录成功也不解除业务渠道暂停或逐帖审核。DM 验收须继续核对当前具体授权，不能从登录授权推导发送授权。

[#674](https://github.com/ban12-project/F-Trade-Platform/issues/674) 的间歇性启动与出口观察问题仍开放。PR #691 修复历史 checkpoint 提示残留，PR #692 补充出口失败分类；两项完整 CI 已通过并合并。包含两项修复的候选运行时已通过真实浏览器 smoke、合成原生档案跨停启恢复、节点启动和空闲退出验证；生产替换仍待单独核对，不能将合并或候选验证当作线上交付。
