# 产品证据原文件名修复 — 2026-10-07

关联 [#517](https://github.com/ban12-project/F-Trade-Platform/issues/517)，来源验收范围见 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)。这是资料选择与可追溯性的实现缺口；正式业务总验收保持 pending。

## 可复现问题与修复

四份获授权参考 PDF 已完成生产上传与完整私有回读，但实际产品表单的六个 PDF 选项仍只显示文件类型、密级和短证据编号。上传回执已保存原文件名，证据查询未使用它；仅凭选项无法辨认应绑定的原件。发现时未保存任何生产产品事实。

`listProjectEvidenceOptions` 现在仅在回执的文件路径、证据编号和人工上传者均匹配时采用原文件名；旧来源或不匹配回执保留原标签。原证据记录、证据编号、来源定位引用及项目授权范围不变。已有文件无需重新上传，人工、批量和模型导入使用同一份来源选项。

返回给页面的对象仍为原有五个字段，不增加私有路径、上传者、回执或原始数据库记录。回执文件路径的既有唯一索引支持关联，无数据库迁移；显示继续使用现有 Select 文本内容。

## 验证结果

- 新增真实 PostgreSQL 回归在修改前失败：实际上传结果仍是通用标签，未返回期望文件名。原失败日志保留；修改后完整文档上传套件通过。
- 覆盖同字节不同文件名、中文文件名、旧来源回退、不同路径/证据/上传者及非人工来源拒绝关联、已领取回执过期后的来源身份保留。
- 非成员仍被拒绝；已关联项目的 viewer 可以辨认来源，另一个项目的成员看不到未关联的他人资料。页面对象的五个字段通过精确键集合检查。
- 独立证据上传 PostgreSQL 套件首次因使用未获测试脚本许可的数据库名称在连接前拒绝运行；改用同一本机测试集群的许可名称后通过，未放宽保护条件。
- 实际 Next 开发应用展示四份参考 PDF 的原文件名及旧标签回退，选择后正确显示对应文件名和证据短编号。React 检查确认实际产品表单组件及来源选项参与渲染；检查工具对嵌套属性会截断，完整对象边界以数据库回归为证据。
- 初次使用 IP 地址访问时，当前 Next 开发服务器拒绝跨来源的热更新及字体请求，导致表单未正常交互。使用服务器提供的规范 localhost 地址后交互正常；未关闭来源检查或改动项目配置。
- 类型检查、修改文件的格式校验及差异空白检查通过。开发服务器报告浏览器错误和编译问题均为空。

本机记录与原件页图仅留在忽略目录，不提交原文件名、产品编号、工程参数、文件哈希、生产对象编号或认证状态。

## 验收边界

本次本机选择检查没有新建产品事实或读取已清理的临时云原件。生产修复须在合并后独立确认部署版本，再使用已有参考文件验证选择、逐字段绑定和授权来源预览。

目录类别可以支持产品类型；无明确语义的复合规格、仅标作部件号的数字以及组件与总成不同栏的参数，不能自动转成工程字段或 OE。来源核对只允许形成有证据的部分测试草稿，不补全未知事实，不替代完整真实 SKU/图片、Product Ready 或正式业务 Go。
