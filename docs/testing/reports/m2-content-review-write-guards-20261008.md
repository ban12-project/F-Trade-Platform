# M2 内容 Gate 01 审核写入授权回归（2026-10-08）

本次处理 [#547](https://github.com/ban12-project/F-Trade-Platform/issues/547) 和 [#548](https://github.com/ban12-project/F-Trade-Platform/issues/548)。所有测试业务记录、产品事实、营销文本和证据均明确标记为 SYNTHETIC，只用于研发验证。

## 已复现问题

在真实 Content Server Action、现有授权逻辑和 PostgreSQL 中，先观察到内容记录锁等待，再撤销审核角色、删除会话、封禁账号或令会话过期。修复前四种情况均返回成功，内容进入 `CONTENT_APPROVED`、版本变为 2、Gate 批准并新增一条审核审计。这证明请求开始时的身份检查不能覆盖等待保存期间的权限变化。

真实签名登录的内容审核页面首次选择决定时还出现 Base UI Select 从非受控切换为受控的控制台错误；对应页面测试实际失败。没有通过重试、增加超时或预选批准规避错误。

原内容审核只校验审核证据引用的格式，未核对证据存在及当前项目使用权限。本次复用现有项目证据授权与关联规则，将它纳入同一审核事务。

## 实现

`decideContentReview` 必须接收当前 actor、session 和 project 身份。取得项目、内容和待审 Gate 锁后，重新检查有效营销项目、编辑权限、当前项目拥有的 `marketing_content` 关联，以及数据库中的当前账号角色、封禁状态和会话有效期。授权锁持续到事务完成，权限撤销与保存按实际锁顺序串行化。

审核证据必须已经持久化，且属于当前项目或由当前审核者上传；证据关联与 Gate 决定、内容版本、工作流和审计在同一事务提交。证据关联等待结束后再次按当前时间检查会话自然过期。失败时整个事务回滚。

Action 返回受控中文提示，未知异常、SQL 信息、私有内容、来源地址及凭据不传给页面。已有版本和待审请求校验继续生效。内容审核 Select 的空值使用 `null`，仍要求审核者明确选择；失败保留决定、证据引用和备注。

## 验收边界

本次通过的是实现回归和受托页面审核。未新增或修改领域 JSON 契约、数据库结构或迁移；调整的是内部审核写入函数必须携带当前身份的调用约束及审核证据核对。
