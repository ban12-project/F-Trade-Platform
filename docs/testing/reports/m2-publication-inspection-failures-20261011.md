# M2 发布页面检查的固定失败类别 — 2026-10-11

接续原 [#156](https://github.com/ban12-project/F-Trade-Platform/issues/156) 和已部署的 [PR #586](https://github.com/ban12-project/F-Trade-Platform/pull/586)。生产检查在一次性票据接受后返回空白 HTTP 403，不能区分租约、私有候选、受控 tab、浏览器调用或响应校验失败。生产原持久浏览器、镜像／应用部署、当前身份与期限边界已有核验；这些证据尚不能证明页面检查或发布通过。

本补充把检查器自身的失败限定为五个固定类别：active、tab、candidate、browser、response。Gateway 只在同源一次性票据已接受、任务仍存在且为当前活跃交互任务时返回 HTTP 422 与版本化的最小类别。未授权、重放、伪造异常以及检查期间停止／替换的任务仍返回空白拒绝；原异常消息、堆栈、正文、账号、选择器、URL 和 Cookie 不进入响应。

应用通过严格 Zod 契约读取失败类别，保留 8 KiB 上限，并在归类前重新检查当前数据库授权、任务期限和源绑定。响应包含额外字段或未知类别时拒绝；撤权后不返回分类错误。失败检查不写成功观察审计。现有 Action 继续显示受控错误，不把任何类别解释为产品事实审核或发布权限。

此改变提供后续真实诊断所需的边界证据，不修改私有候选日期、manifest 开关、逐帖批准或历史 unknown；不增加网关日志验收。本次整体仍沿用政策 1.1.0 的用户范围排除。真实失败类别、最终原因修复与页面成功观察须在同一 Issue 继续核验，不能由合成测试推导。

已另行核实实际 Agent 的候选目录变量、固定挂载、进程身份与私有权限，以及持久 VM 启动 Compose 中的相应绑定。缺少目录配置这一假设被实际结果否定，没有据此修改生产启动配置。

## 验证

- 固定类别与原始错误隔离、晚停止／撤权、同源一次性票据及原接管／出口回归共 52 项通过。
- 原生 Node 24 离线镜像载荷及缺失固定资产负控通过。
- Action 认证、严格输入、可信服务端身份与错误隐私回归通过。
- TypeScript 7 和改动文件 Biome 错误级检查通过。
- 独立 PostgreSQL 17 的 26 个边界场景通过，包括分类响应的严格字段、未知类别、迟到撤权和不写成功审计。最终 CI／镜像发布、生产版本与真实页面结果在本 PR／原 Issue 的回执更新；未验证的结果不写成通过。
- 原生镜像 smoke 新增实际 Firefox HTTP evaluate ABI：启用合成 access key，未鉴权拒绝；在离线空白页编译未改写的固定程序，并验证其页面来源阻断。真实镜像执行由双架构 CI 验证；不会访问 Facebook、使用代理或真实账号。

所有自动测试使用明确标记的合成输入；数据库测试限定独立 loopback 测试库，禁止外部 I/O。实际媒体上传、平台接收、逐帖授权及自动回执仍待验收，独立发送者入站按用户决定暂缓。
