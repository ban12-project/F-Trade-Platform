# M2 应用审计与 Workflow 内容保留核对 — 2026-10-10

接续原 [#122](https://github.com/ban12-project/F-Trade-Platform/issues/122)，在用户明确排除网关侧日志验收后，完成生产视频相关审计的嵌套字段核对，以及托管营销 Workflow 当前可读／已过期内容检查。政策 1.1.0 记录这一直接范围修订；90 天、coda 责任、原始来源保护和独立发布门禁保持。

## 用户范围决定

用户在本次会话明确要求不需要核验网关侧日志。按上下文，将 model_gateway_logs 排除于本次 M2 验收，不继续索取网关管理入口、保留设置或清除回执。排除项的保留状态仍为 not_verified，不能写成未存储正文、零保留或已清除。此决定与证据边界见 [ADR 0007](../../decisions/0007-marketing-video-release-policy.md)；其他模型服务副本不因本项排除自动通过。

## 应用视频审计

生产只读事务按视频聚合、视频相关 subject/action 及处理／生成任务引用扩大关联检索。当前结果为 **29 条审计、45 种嵌套叶子路径、148 个实际叶子值**。逐路径白名单和类型／枚举验证通过：标识、媒体引用、摘要、审核决定、布尔状态、版本／计数及媒体技术测量；没有发现提示词、剪辑处理正文或供应商原始响应。旧 video_advisory_review 表为空，处理任务失败正文为空，生成任务仅有失败码字段且当前失败码记录为零。

此结论覆盖本次当前视频关联审计 metadata，不代表所有应用业务表、日志、证据文件或未来新增审计自动通过。应用正常 video payload／审核自由文本及工作媒体仍由现有 90 天执行负责。没有修改审计记录或禁用追加审计触发器，也没有删除真实资料。

辅助盘点首轮误查生成任务中不存在的 failure_message，事务只读失败；按当前 schema 改为 failure_code 后通过，未修改数据库。其他字符串最初保持待分类，随后逐字段验证真实值与允许枚举，不把“键名安全”当作“内容安全”。

## 托管 Workflow

使用现有 Vercel CLI 授权及当前安装的 Workflow 4.8.8／CLI 4.3.12，按生产项目和两个营销工作流分别读取。必要解密经官方 SDK 的审计记录密钥领取完成；凭据、密钥与业务对象标识不写入 GitHub。

| 核对项 | 当前实际证据 |
| --- | --- |
| 生产运行清单 | AI 初稿 4、渲染 4，共 8；两清单均 hasMore=false，当前均 completed |
| 数据期限 | 8 个 expiredAt 均约为 completedAt 后 7 天；这是当前运行元数据，不把期限改成创建后 90 天 |
| 当天可读运行 | 2 个；解密的运行、步骤及创建事件输入仅 jobId/videoId/actorId，8 处输入与实际数据库任务绑定逐项相同 |
| 当前步骤 | 每运行一项，共 8；步骤分页检查无后续页 |
| 当前事件 | 每运行 6 项，共 48；通过 SDK 继续取游标至末页，未仅取 CLI 首页 |
| 可读输出／错误 | 当天两项步骤与运行输出为 void，可读错误为空；事件包含生命周期与运行技术上下文，没有处理正文 |
| 已过期运行 | 6 个旧运行输入及相关输出／错误字段显示 data expired；共 48 个过期数据字段，不能重建其原内容 |
| Workflow streams | 当前 8 运行的 streamStorageBytes 均为 0 |
| 历史元数据 | 过期后运行、步骤和事件标识仍可列出；原过期／unknown 历史没有重排或删除 |

CLI 的 steps/events JSON 输出去掉了 cursor/hasMore，初次读取不能证明完整。随后非 JSON 检查发现事件 hasMore=true；通过相同生产 SDK 补取第二页，实际第二页为空且 hasMore=false，确认 48 项完整。没有因读取超时重启运行，也没有把客户端展示文案当作物理删除回执。

旧字段的过期占位与官方序列化 expired stub 对应，可证明当前正常管理读取不可取得这些正文。不能据此声称供应商内部字节已擦除，也不能声称已知道旧字段过期前的原始内容。当前可读运行的标识输入与 void 输出已直接验证，不只依据工作流源码推断。

## 政策版本与验证

新清理记录使用 1.1.0；此前 1.0.0 任务仍保留原版本。现有 PostgreSQL 回归对新清理的期待改为读取当前政策版本，旧版本等待任务仍作为兼容场景保留。应用保留天数、截止判断、来源保护及权限不变。

本地类型／格式检查通过。保留测试最初缺少专用 loopback 数据库，被自身安全检查拒绝；本地 Podman 启动命令虽返回成功，随后实际 VM 状态为停止且连接失败，未创建测试容器、未连接生产数据库或安装系统 helper。完整保留／来源保护及旧版本任务回归以本 PR 最终 CI 的专用 PostgreSQL 结果为准。

网关日志是用户指定的范围排除，不再作为本次前置。当前应用审计 metadata 及 Workflow 可读／过期数据已有直接内容证据；实际生产 90 天到期对象与 Blob 删除、其他模型服务副本、Vercel 运行日志及数据库历史副本的物理清除／恢复演练仍未由本次检查证明。没有人为改写真实对象时间或制造到期业务数据。
