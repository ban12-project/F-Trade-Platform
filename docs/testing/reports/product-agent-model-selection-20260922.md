## 选择建议与失败解释

当前建议把 **Kimi K3 作为质量优先的下一轮候选，MiMo V2.6 Flash 作为延迟优先的候选**。Kimi 本轮成功最多，但只比 Flash 多 3 次、比 Luna 多 2 次，且中位耗时约为 Flash 的 4.8 倍；20 个合成场景不足以证明统计意义上的稳定领先。不要据此自动切换所有项目模型。

- Flash 与 Pro 最终同为 53/60，Flash 的 P50/P90 均更低；本集没有证据支持为 Pro 的额外等待买单。不能推断其他任务也如此。
- Luna 为 54/60，处于中间位置。其文本模式首次契约有效率 100%，说明把字段类型说清楚也能显著减少格式问题，不能把所有改善归因于强制 Schema。
- MiMo V2.5 的 56/60 最终失败都是超时，不适合本轮端点默认配置和 75 秒交互预算。这不等于其事实推理能力只有 6.7%；若以后调整思考设置或预算，必须作为另一配置重新比较。
- Ultraspeed 在现有 Token Plan 端点预检报模型不支持，不需要新 API key 来解释本次结果；未测得质量，不能排末名。
- 所有可用模型均未达到本合成回归集的严格 60/60 gate。测量完成不等于上线验收通过。

主要失败集中在 c-02/d-02：产品没有整件 OE，组件栏却有一个 OE。Flash、Pro、Luna 在这两个用例各失败 6 次；Kimi 失败 3 次，其另一次失败发生在 c-01。原始诊断显示这些模型存在将组件 OE 提升为整件 OE 的尝试，生产来源校验将其拒绝。Kimi 的这些错误尝试在纠错时耗尽预算，所以最终错误分类为 timeout，不能把“最终契约拒绝 0”解释成它从未产生错误事实。

Flash 的 7 次纠错仅恢复 1 次，Pro/Luna 各 6 次和 Kimi 的 3 次纠错均未恢复。当前通用纠错提示对这类语义错误帮助有限。后续应把组件/整件归属作为预先定义的训练外回归重点；不能在看过这些答案后修改提示词，再把同一批用例称为独立留出验收。

Schema 约束仍推荐保留：它减少非法结构并允许未知事实用 null 表示，但无法阻止“类型正确、归属错误”的 OE。来源证据校验、人工审核和严格状态边界必须继续保留。

正式选择前，需要经授权的真实工厂资料留出集，覆盖多产品表格、组件归属、跨语言、缺失与冲突以及真实图像/OCR；事先约定成功率、延迟和零越权/零无来源工程事实的验收线。本次仅交付可复现的候选筛选依据，不声称这些外部资料已验收。
