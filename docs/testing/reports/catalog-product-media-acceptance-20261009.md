# 目录产品图的生产媒体绑定验收 — 2026-10-09

接续原 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)／[#5](https://github.com/ban12-project/F-Trade-Platform/issues/5) 及 [#122](https://github.com/ban12-project/F-Trade-Platform/issues/122)。五个 A 组 SKU 已有各自来源图片，但生产中没有可复用产品媒体，实际页面显示无法制作视频。完成正常上传、逐素材权利登记及本次委托审核后，五个产品均显示 `VideoReady`，各有一张可用于确定性剪辑的素材。

## 来源、授权和审核

重新视觉核对原目录完整图片页、各自编号与五张既有裁图；每张图仍对应自己的 SKU，裁图哈希与生产原始图片绑定一致。图像来自目录图片框，没有生成外观，也没有把目录图写成当前库存实物。所有原件、逐条产品值、裁图区域、对象标识及审核记录留在受控私有记录。

沿用[已取得的真实来源及素材用途授权](../../reference/README.md#当前真实来源与素材用途授权2026-10-08)。另将本次用户指令、逐图来源、授权解释及审核边界整理为私有证据，明确文件由 Agent 整理，不能冒充独立工厂签章或第三方许可证。实际生产的权利和审核均引用这一已持久化、已加入当前项目的证据。

五张图片通过正式页面上传至 Private Blob，由服务端重新确认当前身份及上传回执，完整核对私有字节，再由生产 Sandbox 的 ffprobe 探测图像尺寸。登记范围为目录产品图的剪辑与营销公开使用；付费广告、图生视频和生成式视频参考权限均未授予。没有素材许可终止日输入，未补造日期；90 天工作资产保留期不充当版权许可到期日。

登记与批准分别提交。应用审核主体是当前登录的 coda，备注明确本次执行者为用户委托的 Agent；每张素材各有一条登记和一条批准审计。素材许可不代替逐帖发布确认，也不确认尺寸、材料、适配、库存、报价或交期。

这次核验调用当前生产页面和只读数据库／私有存储读取，未绕过正常写入边界。没有新增产品、模型请求、视频草稿或成片，没有渠道发布、客户消息、真实 RFQ、报价或交期决定。

首轮辅助查询误用了上传回执中不存在的状态列，第二次亦误用了不存在的完成时间列；两次只读失败保留。按当前 schema 改为验证真实证据关联和项目关联后通过，没有据此修改数据库。页面链接文字无空格使首轮批次链接定位失败；改按已观察文字匹配五个详情链接后完整加载通过，没有重复登记素材。

## 尺寸识别仍未解决

同一冻结 30 格尺寸期望另有两组离线诊断：希腊文字／中文模型的 240 次整格读取无逐字匹配；逐字形分割的 666 次读取中，英语加希腊语及英语加 Greek 脚本模型均只匹配 16／30 格，仍有高置信度字面差异或未读出。

后者两模型联合诊断耗时 184.5 秒，且直接拼接字形未证明原文空格保留；单模型完整页面的生产预算尚未验证。结果保留为诊断，不加入生产模型、不替换符号、不降低置信度门槛、不改冻结期望。生产仍沿用[已交付的部件号／弹簧复读](scanned-disc-glyph-recovery-20261009.md)及其 85／115 原格匹配结果。
