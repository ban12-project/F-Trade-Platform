## 实际失败与修复

三个修改前的隔离探针调用真实 Server Action，使用实际 PostgreSQL 并观察到线索行等待。原请求会话随后被撤销、当前角色被取消销售权限，旧实现仍返回成功，持久化一个 queued 回复任务、一个加密 outbound 消息和一条提交审计。另外两个探针分别让 60 分钟回复窗口、入站消息保留期在等待中到期，旧实现仍提交相同写入。原失败日志与脱敏摘要保留；没有实际外发。

请求现在从服务端取得 actor／session／project 身份。在业务行、消息、渠道和 Gate 03 来源等待结束后，事务重新核验并锁住当前未封禁销售角色、匹配且未到期的会话、活跃销售项目、可编辑成员资格及项目拥有的线索。旧的用户编号调用和不匹配身份会被拒绝。

回复窗口、保留期与交期确认采用等待后的当前时间。所有写入完成后的最后检查再次核验会话和时间边界；期间自然到期会回滚任务、加密消息、线索版本／内容及审计。原消息正文加密、逐条人工确认、渠道暂停、重复凭据去重和 unknown 结果禁止重试规则保留。

Action 只返回状态、提示及线索编号。已知业务拒绝保留明确提示，未知数据库／认证错误不返回原文；事务已提交后的缓存刷新失败保留真实成功结果，避免把已经排队的回复呈现为未提交。
