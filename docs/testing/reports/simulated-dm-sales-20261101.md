# 模拟 DM 至商机流程（2026-11-01）

关联 #26、#32。用户明确授权“可以模拟 DM 走完后面的流程”。本轮复用已有
reference 产品，销售链路按模拟验收完成，不再等待真实客户或可发送私信的账号。
发布和真实 DM 入站仍延期；最终 Go/No-Go 未由 Agent 代替决定。

## 输入与运行范围

- 应用基线：`2eb585f8ed18fa0cb1d13718bfacf03436ba48e7`，冻结依赖安装及默认
  Turbopack 生产构建成功；未修改应用代码、门禁或编译配置。
- 只读查询本机配置连接的数据库，选取活跃 REFERENCE 项目中一条
  `PRODUCT_READY` 产品 payload，复制到独立本机 PostgreSQL。原 payload
  在最终断言中逐字段相等；未新增产品事实、未写回来源数据库。
- 模拟会话明确标记 MOCK／SIMULATED。首条消息引用该产品的类型与 OE，
  后续消息继续引用同一产品。数量、目的地、价格、交期、客户与审批身份均为测试值。
- 消息和会话预置在独立数据库，随后通过正常生产构建页面／Server Action
  完成销售写入。模拟认证仅在本机测试环境使用；没有伪造线上用户会话。
- 本轮不验证平台接收、真实 DM 采集、入站传输或真实人工批准。没有连接发送 worker。

## 观察结果

| 步骤 | 已验证结果 |
| --- | --- |
| 读取模拟 DM | 页面“从客户消息整理建议”从持久化加密消息提取类型和 OE；此时 RFQ 仍为零，需另行保存 |
| 补齐询盘 | 先保存不完整需求，再补齐数量／目的地并确认，最终 `RFQ_READY`；原会话关联保留 |
| 模拟人工报价 | 引用同一产品和 RFQ；先退回，再修订并审批，旧版本审批被拒绝；最终登记 `QUOTE_SENT` |
| 交期 | 通过请求与模拟人工确认进入 `DELIVERY_CONFIRMATION_CONFIRMED`；未确认时回复仍被阻断 |
| 跟进 | 未读、已读未回、嫌贵、以后采购、要样品、询问交期六种场景完成；回复均停在本机队列 |
| 商机 | 页面显式确认后为 `OPPORTUNITY`，高意向 75 分；数据库审计包含 `lead.opportunity_confirmed` |
| 产品与外部影响 | 产品 payload 不变；零真实消息投递、零线上业务写入 |

最终一次完整浏览器场景通过（17.0 秒，含服务启动 20.9 秒）。随后独立读回
同批记录并检查最终页面截图。最终状态为 RFQ Ready、报价已登记发送、交期已确认、
有效商机；“已发送”是模拟凭据登记，实际回复任务仍 queued，不能解释为外部投递。

## 失败与修正

容器镜像获取被本机代理拒绝，改用独立本机 PostgreSQL；没有修改代理或线上网络。
首次配置将构建工作目录指向临时目录，构建未启动；明确应用根目录后构建成功。
第一轮页面检查未提取 OE：初始模拟消息在 OE 后附句点，不符合现有严格 token 解析。
改用字段分隔符后完成全链。截图检查又发现后续消息仍使用旧 fixture 产品描述，
统一为本轮产品后重新完成全链；没有放宽解析、门禁或测试断言。
