# M1 / M2 编辑与来源审核缺口 — 2026-10-07

关联 [#523](https://github.com/ban12-project/F-Trade-Platform/issues/523)。这是对实际页面的实现补缺，延续 [M1 / M2 状态核对](m1-m2-reconciliation-20261007.md)，不改变真实工厂与渠道试点的验收条件。

## 可复现问题与修复

| 范围 | 修复前的浏览器观察 | 修复后的行为 |
| --- | --- | --- |
| M1 来源逐字段对照 | 同一来源中，产品名称有原文片段，产品编号无片段；编号的独立核对提示被过滤掉 | 每个关联字段展示原文片段或打开原件核对的提示 |
| M2 等待期间编辑 | AI 请求等待期间改写正文，返回后正文变成生成内容 | 比较请求发起时和当前表单；任一选择或文字不匹配时，整份旧初稿不填入，并提示按当前内容重新生成 |
| M2 产品选择 | 请求等待期间切换产品，旧产品初稿仍填入新选择 | 当前产品、事实、内容类型、营销目标和客户选择必须与请求匹配 |
| M2 并发操作 | 生成与创建待审内容可交叉排入请求队列 | 生成和送审互斥；输入仍可编辑，错误返回后可重试 |

请求使用现有服务端 Action，身份、授权、Zod 校验及 Product Ready 门禁继续由服务端执行。结果在当前项目／记录的有效请求中处理，离开记录会使旧请求失效。生成结果仍是待人工审核文案。

## 验证

- 修复前，正文覆盖、产品切换错配和来源缺少逐字段提示三个浏览器回归用例失败，实际收到旧生成文案的观察保留在本地测试日志。
- 修复后，14 项专项浏览器检查通过：正常五字段填入；五个文案字段的等待期间编辑；产品／事实／类型切换；营销目标／客户变化；失败后重试；生成与送审双向互斥；混合来源片段覆盖。
- TypeScript 检查通过。Next.js 16.3.8 开发环境、Turbopack、Cache Components 与两个 React Compiler 配置保持启用；运行时错误及主动编译检查无错误。
- 使用合成测试夹具并拦截生成／送审响应，无实际模型请求、工厂事实确认或业务写入。服务端真实身份认证、数据库写入和版本保护继续由完整 CI 的数据库浏览器套件验证。

私有调试输出位于本地忽略目录，不提交原始工厂资料、客户信息或凭据。完整 CI 的最终结果记录在关联 PR。
