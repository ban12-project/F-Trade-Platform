# M1 产品资料上传：当前身份及有效期 — 2026-10-08

## 修改前的实际失败

真实上传 Server Action 与隔离 PostgreSQL 探针中，私有文件读取开始后删除原请求会话，并把当前用户改为无产品写入权限的角色；读取继续后，旧实现仍返回 success，新增一项 evidence、一项项目来源关联及已认领回执。探针只使用明确标记的虚构 CSV，私有文件传输受控，外部业务请求为零；原失败日志及脱敏摘要保留。

## 修复后的行为

上传领域接口要求服务端提供 actor、匹配 session 和 project 身份。回执签发、传输重试及文件核验后的保存事务均重新读取当前未封禁的产品写入角色、会话、活跃营销项目及可编辑成员资格，并锁住授权记录直到提交。旧的 actor-only 调用和身份不匹配被拒绝。授权锁遵循已有产品写入顺序；不在私有文件读取或外部签名期间持有数据库事务。

回执和签名有效期至多为 15 分钟，且不超过当前会话期限。外部签名生成后及 SDK 完成 presign 后再次校验当前身份、回执内容及期限，再返回上传凭证。签名失败或权限变化可能保留已预留的未认领回执，但不会向客户端返回凭证；预留回执本身在 INSERT 等待中到期则整笔回滚。

文件读取后的保存事务重新核对回执所有者、项目、用途、私有路径、原文件名、类型、大小和期限，避免将读取前的元数据用于已变更的回执。已有证据再次认领还要求哈希、大小、路径、类型及人工上传者一致。原并发幂等、独立来源、不可覆盖、25 MiB 资料／5 MiB 图片限制、图片解码和有限传输重试均保留。

最后一个保存语句结束后再次检查会话和回执期限；等待期间自然到期会回滚 evidence、来源关联及认领更新。已提交后的缓存刷新失败保留成功结果。认证及未知存储／数据库错误只返回固定安全提示。单产品、流式导入、图片和目录入口均传递完整服务端身份；单产品在模型配置等待后也再次检查当前授权。

## 首轮 CI 的浏览器过期夹具修复

首轮 `de5b7ffc` 的仓库验证、产品数据库回归、Harbor 和生产构建通过；浏览器普通组 270 项通过，登录态组 180 项通过、1 项失败。失败的既有视频 AI 初稿用例把有效会话缩短至 650 毫秒后等待自然到期，但后台登录态读取可以经 Better Auth 合法续期，测试未保证提交时该会话确实已失效。

已核对安装的 Better Auth `getSession` 及 cookie 实现，并在独立合成会话探针中观察到当前数据库期限被正常读取延长七天。另在原浏览器夹具中显式触发一次正常认证读取，把本地开发环境的等待窗口设为 5 秒以容纳请求耗时：数据库期限延长七天，随后同一 AI 初稿请求进入队列，原拒绝断言失败。首轮 CI 未记录数据库期限，续期根因是由库实现、CI 行为及这一实际复现支持的判断。过期用例改用库支持的签名非持久登录 cookie，避免后台续期；释放业务行锁前额外读取数据库，确认会话已到期或已被认证库删除。保存、复制、创建、AI 初稿和渲染的原自然到期等待、固定拒绝提示、保留输入和零业务写入断言均保留，未改变生产会话策略，未启用测试重试。本地首轮还发现按钮点击会隐式等待一次页面刷新，导致在持有业务行锁时尚未走到过期设置就超时；两个受控等待入口取消点击后的隐式导航等待，由已注册的 POST 响应及原页面断言确认请求完成。
