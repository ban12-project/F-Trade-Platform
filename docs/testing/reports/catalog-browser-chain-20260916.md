# 同批目录草稿的本机流程验收

关联 #340、#268、#26。当前为阶段记录，整体 Go/No-Go 保持待人工决定。
原始参考资料、模型正文、私有地址及记录标识留在本机忽略目录；这里只提交聚合结果。

## 资料与执行边界

起点是 [目录导入验收](../product-catalog-import.md) 中由参考 PDF、实际私有上传和实际模型
产生的同一批 20 条草稿。它们原本均只有来源支持的目录编号，不能批准为完整产品。

在专用本机数据库中，按既有 MOCK 测试授权准备独立补充来源：名称明确包含 MOCK 与
“not factory facts”，类型和 OE 也只是测试值。该补充文件及证据记录仅在本机，
没有冒充新的云上传或工厂资料。原始草稿快照和目录候选来源保留，测试不会改写原 PDF。

## 已执行

- 对一条原始不完整草稿执行浏览器模拟批准，系统拒绝；产品及待审审批记录均不变。
- 同一批 20 条草稿通过真实页面依次退回、修订、再次送审和模拟批准。
  数据库回读确认 20 条进入测试环境的 `PRODUCT_READY`，各有一次拒绝与一次批准。
- 目录编号及 `source_ref` 保持不变。修订后的编号绑定原件证据，新增的名称、类型、OE
  分别绑定独立 MOCK 来源；原先细粒度页位置仍保存在原始快照与目录候选记录中。
- 20 条内容经真实浏览器调用已配置的实际模型生成并保存。正文均逐字保留相应测试名称
  和测试 OE；标题、正文、行动提示及视觉说明已逐条检查，明确保留 MOCK 使用边界，
  视觉说明限于抽象背景和文字卡片。没有真实供货、性能或价格承诺。

- 20 条内容随后通过真实页面完成模拟审批；数据库回读确认正文与事实引用保持不变。

以上批准均为测试自动化模拟，不是真实人工或工厂审核。模型只在这里验证带有合成补充
的内容路径，不能据此宣称原目录工程事实抽取完整或生成文案适合直接公开发布。

## 同批销售流程

20 条记录均通过生产构建的浏览器完成模拟询盘补齐、RFQ Ready、报价退回修订、
Gate 02、模拟发送凭证登记、Gate 03 交期确认、跟单评分及显式商机确认。
首条独立运行通过，其余 19 条运行通过；最终数据库联结审计确认：

- 20 个 RFQ Ready、20 个 `QUOTE_SENT`、20 个 `OPPORTUNITY`。
- 每条报价仍引用对应的已导入产品，内容与产品 payload 在销售流程中未改动。
- 旧版本报价审批被拒绝；未确认交期时回复被阻止；未达到条件时商机确认不可用。
- 20 条加密回复均停留在本机测试队列 `queued`；没有连接外部 worker，没有真实发送。

营销与销售使用关联项目，销售侧通过明确产品引用关联同一批记录；模拟入站消息和
测试证据在本机预置，业务状态转换通过真实 UI/Server Action 执行。产品/内容部分使用
开发服务器，销售部分使用相同代码的生产构建；这是同批持久化记录上的连续验收，
不是一条覆盖邮件登录、真实渠道入站或线上部署的单脚本运行。
