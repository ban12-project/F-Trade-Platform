# 手动事实录入与原图保存检查 — 2026-10-10

接续原 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)／[#5](https://github.com/ban12-project/F-Trade-Platform/issues/5)，按最终事实审核政策 v2.0.0 推进 20 个真实来源样本。当前生产有十条已审核产品，另外十个预期缺身份事实的槽位尚未建立完整生产处置记录；该观察不等于新批次验收通过。

## 发现与修复

原手动录入和修订表单不能附带原始产品图片，只有自动抽取入口支持。这使人工补录路径无法保留带图负例的外观审核上下文。现在两个手动入口使用已有私有上传协议保存 PNG／JPEG，每张最多 5 MiB，每个产品合计最多四张。客户端使用共享 Zod 文件校验与现有 Field／Input；服务端独立校验回执、上传主体、用途、项目及文件完整性，不发送图片或手动事实到模型。

草稿与原图关联、待审核记录、工作流和审计在同一事务保存；修订追加原图并重新送审，已有原图保留。审计记录创建时的图片引用或修订新增的图片引用。图片不进入工程字段证据，文字事实错误绑定图片会被拒绝。带图产品批准继续要求明确图片一致性确认；缺少 OE／完整已核实适配等关键事实仍不能 ProductReady。

两个 Server Action 传入当前用户、登录会话和项目。实际写事务重新锁定并验证身份和成员权限，保存结束再次检查登录有效期。原始数据库与上传错误不会回传给客户端。应用页面保护不能代替这些保存边界。

实际生产从修订页转到新建页还暴露了标签关联错误：后台保留的旧表单与新表单共用字段 ID，可访问名称变成重复文本。事实、证据选择、图片、资料库和审核控件现在使用实例独立的 React ID，未保存状态也按实例区分，保留页面不会干扰当前输入。受保护的测试页保留一份隐藏旧表单，浏览器验证当前字段仍只有自己的标签。

手动最终事实复核还不能用旧的必填数值格式如实表示未重跑的效率诊断。v2 结果现允许显式 `null`，必须在 `unmeasured_metrics` 列出并说明原因；已测数值不能同时列为未测量。历史 v1 保持原数值规则，关键事实、来源、审核和纠正审计仍须完整。

## 已取得的证据

- 类型、格式和现有产品契约回归通过；既有自动抽取图片约束、逐字段来源和修订历史回归保持。
- 实际 Action 回归验证图片引用及当前身份传递，重复回执／上传失败不进入领域保存，私有错误不外泄。
- 独立本机 PostgreSQL 合成测试验证手动创建和修订的原图持久化、审计及重新送审；带图批准缺少明确确认时被拒绝。
- 外项目图片、重复图片、超过上限和图片作为文字事实证据均被拒绝；失效或外主体登录、失去项目写权限均不留下产品、图片、审批、工作流或审计的部分写入。
- 通过实际图片表锁观察到创建事务正在等待；等待期间登录到期，解除锁后保存末尾的有效期检查使整项事务回滚。
- 开发框架检查与实际浏览器核对手动表单；浏览器回归覆盖五张图片被客户端拒绝且不发起上传或保存请求，最终执行结果以 CI 为准。

上述数据库材料全部为标记的合成数据，不代表工厂事实、生产 Blob 上传或真实 Gate 01 已完成。最终 CI、squash、正式部署与真实 20 槽位处置核查追加在同一 PR 和原 Issues。实际来源、图片、事实、缺失项和审核记录保存在私有业务存储；历史运行不覆盖。
