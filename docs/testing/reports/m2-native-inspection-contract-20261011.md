## 改变

固定页面程序的未知执行异常现在只返回预定义 `page` 标记；`response` 专门表示有界返回体／观察字段无效。仍丢弃原始异常、正文、选择器、URL 和账号信息。来源不符保持 `tab`，选择器语法问题保持 `candidate`。新标记只有经过原同源、一次性票据、运行任务和当前授权检查后才能返回；失败不产生成功观察审计。旧节点的 `response` 仍可由应用识别，不能从旧类别重建原因。

原镜像测试只证明空白页拒绝与程序可编译。新增仅在 `--network none` 测试容器挂载的 fixture，通过固定上游插件钩子拦截导航，返回合成 DOM，其他请求全部拒绝。配置由正式配置临时派生，fixture 不进入运行镜像。真实 HTTP 接口调用同一检查器，覆盖以下场景：

- 空编辑器、正确身份、Only me 和隐藏文件输入可观察。
- 已有未发送正文返回非空；正文不进入观察。
- Friends 返回受众不匹配。
- 重复编辑器及错误身份返回未确认字段，不假装通过。
- 非 HTML 文本控件导致真实页面执行异常，归类 `page`，不泄漏异常详情。

空白页来源拒绝、合成 access-key 认证、实际 Firefox profile 偏好及独立 watchdog 退役检查继续执行。测试初始期限从 70 秒调整为 90 秒，以容纳新增场景，仍在 watchdog 原 95 秒上限内，没有自动续期。fixture 变更加入双架构镜像 workflow 的触发路径。

## 验证与边界

本机 Firefox 153 的六个合成 DOM 场景、53 项节点／出口／profile／检查回归、27 项独立 PostgreSQL 授权与隐私场景、Action 认证与错误隐私、TypeScript 7 和 Biome 已验证。第一轮新增 Gateway 测试发现测试替身固定抛出旧类别，修正替身后对应测试通过；不将失败记录删去。本机 Firefox 不是正式固定 Camofox 的替代证据，双架构固定镜像的真实 HTTP 结果以同一 PR 的 CI 为准。

生产原因仍需上线新边界后实际核对：`page` 应继续定位页面执行，`response` 应继续核对返回格式。没有获得当前检查成功、空编辑器／Only me 正式审核、平台媒体接收、具体逐帖授权及自动回执，#156 和 M2 继续开放。独立入站按用户决定暂缓，网关日志按政策 1.1.0 排除且保持未核验。
