# 扫描目录跨行文字边框补缺

关联 #268、#5；继承 [PR #569](https://github.com/ban12-project/F-Trade-Platform/pull/569) 的原始失败与生产检查点。本轮不关闭完整 M1 验收。

## 原因与改动

此前实际运行镜像恢复既定十个样本中的八个。对另外两条的原页、整页 TSV、实际像素行线和单元格复读逐一诊断发现：行线已经存在，但整页 OCR 的文字边框向上吸收了行线。用文字顶部选择上一条行线会裁出相邻两条编号；单元格校验正确拒绝了多编号结果。

现改用整页文字边框的中心寻找真实行线之间的单元格。中心贴近行线时拒绝定位；表头、唯一列界、两个列各自的行界、逐单元格独立复读、至少 60 的置信度、字面编号格式和单一编号要求均保留。文字边框只用于找区域，不能代替复读证据；没有用已知编号补字或从相邻行复制 OEM。

## 已执行证据

- 当前 synthetic 跨行边框回归在未修改的 main 实现上失败；失败日志保留在本机。修复后通过，并检查贴近行线拒绝和单元格裁剪高度，防止退回裁出两行。
- 合成 PDF 实际经 Poppler/Tesseract 和生产转换入口处理；仅扰动整页的文字几何，单元格仍调用真正 OCR。两行各自的编号与 OEM 保留，相邻行 OEM 的负向检查通过。
- 新实现的实际 amd64 Ubuntu 镜像禁网执行三套回归：原生表格／重复／混合空页、套件 OCR、扫描盘片单元格 OCR，全部通过。
- 同一镜像读取已授权原件的相同两个物理页，分别恢复 17／6 条未审核行；既定十个样本的内部编号及各自同一行 OEM 全部与此前冻结的原页核对值逐字一致。十条只覆盖这两个字段，不是整份目录或全部工程事实准确率。

本机初次两页执行中第二页未恢复，原结果保留；单独复测该页时十个样本中的该组五个均逐字一致。不得用本机较新 Tesseract 替代实际镜像证据。全部原件、逐条字段、页面图和诊断输出留在受控本机。云端固定摘要、最终 head CI、合并与生产导入复验将追加在同一补充 PR 和原 Issues。
