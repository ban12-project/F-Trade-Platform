# 同镜像隔离 Sandbox 在线验收

关联 #459、#453、#454、#32。应用基线 `85b7bf2`；目标浏览器原配置 `sha256:0cc22e02fe7a1542036a47b6fc64d84027747cd6eebdabe0192f773cbda42e1f`，Docker OCI manifest `sha256:d11c92125b355a5003d401f02f8f9cb2b467451954e1a8d97438db8bf742b75a`。结论：**既有账号副本在目标镜像下三轮在线身份/出口/会话就绪验证通过**，不代表生产接入或视频自动回执通过。

## 授权与网络来源

所有者本轮直接批准测试审核，授权沿用现有代理并提供代理配置；不再将额外人工测试复审列为本轮前置条件。网络规则来自本次提供的代理 IP，仅放行单个 `/32`。不公开代理地址、用户名、密码、账号标识、页面内容或 cookie。

先只读检查停止备份的隔离副本：旧 Sandbox 留有账号会话、节点配置和已退出的 Agent，未留有可复制的代理主机；数据库代理配置加密。本轮使用所有者新提供的值，不猜测密文、出口地址或历史默认规则。

## 首次失败与纠正

1. WSL Podman Chromium 首次代理测试返回 `ERR_TUNNEL_CONNECTION_FAILED`；独立 CONNECT 探测发现 HTTP 403 且无 CRLF，严格 HTTP 客户端报告 `HPE_CR_EXPECTED`。原因未确认，不能推断为密码错误或代理服务整体不可用。
2. 首次云探测在任何变更前遇到本地 OIDC 上下文错误；通过已登录 Vercel CLI 刷新临时 OIDC 后继续，未导出生产 Secret 值。
3. 初版规则包含空 `allow` 数组；Vercel 保存时省略该字段，精确比较正确拒绝恢复。保留首次元数据，移除可选空字段后，再次读取并确认规则精确一致，随后才恢复。
4. 隔离 Sandbox 的代理请求成功，出口与数据库预期 IP 一致；不经代理访问同一出口检测服务失败。浏览器账号尚未参与此探测。

- 传入既有 1,383,023,083 字节压缩镜像归档并核对 SHA-256；保留原配置及全部 28 个 RootFS 层，未重建镜像。Docker 29.1.3 使用 manifest 身份，不能直接将其 image ID 当作 Podman 配置摘要。
- 账号卷 owner manifest 与只读 broker 账号/节点映射一致；使用独立副本，原生产 Sandbox 和独立回滚备份保持停止。
- 依据本次所有者授权，在隔离容器内生成一小时有效的 `observe-only` 测试配置，沿用既有账号范围和选择器。原私有生产审核文件未改。延长测试配置本身不计通过；通过依据为实际页面返回的身份与就绪观察。
- 同一副本连续创建两个独立浏览器容器，均验证浏览器经代理出口匹配、Facebook 来源及身份匹配、Messenger `ready`。之后停止并恢复同名 Sandbox，创建第三个容器，重复通过。
