# 六种跟单场景的持久化验收

关联 #355、#26、#32。此记录只描述合成测试，不代表真实人工审批或消息投递。

## 已验证

在隔离 PostgreSQL 和 Node 24 生产构建上，通过实际页面及 Server Action 运行完整的
RFQ、报价修订、Gate 02、模拟发送登记、Gate 03、跟单及商机流程。

新增六种场景逐一提交独立的模拟确认凭据，并检查：

| 场景 | 保存的下一动作 |
| --- | --- |
| 报价未读 | 等待后引用报价有效期 |
| 已读未回复 | 询问一个阻碍决策的问题 |
| 反馈价格高 | 询问目标预算并转人工 |
| 稍后采购 | 记录采购时间并请求跟进许可 |
| 询问样品 | 收集样品要求并转人工 |
| 询问交期 | 请求工厂交期确认 |

每种场景均核对保存的 context、next_action、独立队列任务、加密消息正文与审计确认引用；
刷新页面后选项值一致。样品与交期回复保留服务端插入的已确认合成交期，其余场景正文
与输入逐字一致。原有未确认交期阻断和非 HOT 商机阻断继续通过。

最终为原始交期回复及六场景回复共七个不同任务；每个任务创建时均为 queued，
没有运行外部 worker，没有真实发送。最后仍需显式模拟确认才进入 OPPORTUNITY。

## 执行与保留的失败

- 生产构建通过；最终数据库浏览器测试通过，测试正文耗时 35.1 秒，总计 48.2 秒。
- 临时测试配置第一次指向了错误工作目录，应用未启动；配置修正后完成生产构建。
- 第一轮显示断言把下拉箭头计入文本，第二轮定位同时匹配隐藏测量节点。
  两次失败均保留；最终精确检查可见 combobox 内的选项值，未修改应用行为。
- Biome 和 diff whitespace 检查通过。临时运行配置、日志与失败 trace 不进入 Git。

自动判断客户意图、生成回复、自动定时发送或真实渠道接收成功。原有参考资料测试和
