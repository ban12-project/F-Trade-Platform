# M2 视频回执的有界返回滚动

关联 [#598](https://github.com/ban12-project/F-Trade-Platform/issues/598)，补充 [#156](https://github.com/ban12-project/F-Trade-Platform/issues/156)。

## 观察与修复

受控原生 HTTP 核对证明，所选页面向下加载后再向上返回可以读取同一视频帖子内的作者、正文、唯一视频和规范 Reel 链接。单独使用较小的向下距离未读到帖子正文；不能将空壳当作有效基线。当前空编辑器的结构化和截图观察也证明身份、空正文及指定私有受众匹配。这些是页面证据，不是新视频发布回执。

`captioned_post` 新增可选 `receiptScrollBack`，仅接受 1–2000 的整数。配置时，每次进入已审核回执页面先按 `receiptScroll` 向下、再按返回距离向上，随后执行既有加载与回执检查。遗漏配置保持原行为；非此模式或非法返回距离拒绝启动。任何滚动请求失败仍停止，不绕过身份、精确配文、单视频、新链接、媒体摘要或一次点击门禁。

## 已执行验证

新增合成懒加载页面先隐藏帖子，仅在正确先下后上路径后显示。正例在修复前返回 failed，修复后取得唯一新视频回执，并核对基线和发布后两次导航均执行完整滚动。缺少返回配置和返回请求失败的负例均零发布点击、零授权、零回执。

- 完整 Chromium 执行器回归：52 项通过，全部外部请求被拦截为合成页面。
- TypeScript 7 校验、7 项私有候选／页面检查回归和全仓验证通过。
- 原生镜像夹具新增双向 HTTP 滚动契约检查；双架构 CI 结果须以关联 PR 的最终提交为准。该检查证明接口兼容性，不冒充原生页面懒加载或生产发布验证。

页面核对没有点击发布或再次上传媒体。生产私有候选仍沿用原日期和格式范围，发布能力未启用。代码交付后仍需更新受测运行时、复查完整读取路径和当前视频审核，再执行已授权的单次发布及自动回执验收。M2、#156 和真实保留期等未满足条件继续开放；独立入站沿用用户暂缓决定。真实账号、正文、私有选择器、素材、页面截图、发布标识和凭据不写入研发记录。
