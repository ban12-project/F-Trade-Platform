## 确认问题与修复

基线 `main@d611109`。上一轮真实浏览器已证明改名 PNG 的 SVG 在模型生成前被拒绝，但页面只显示“检查项目权限、证据和模型配置”。明确的图片/文件问题被归入未知错误，用户无法选择正确的修复步骤。另查实际非流式产品导入和手动证据 Action，它们通过 `actionError` 把未识别异常的 `error.message` 返回 UI，可能暴露 provider 响应或私有信息；本轮以合成私密标记验证该返回边界，未声称真实密钥已经泄漏。

- 新增应用自有 `ProductUploadError`，只用固定 code/message 表达文件不可用、类型不符、大小不符或超限、图片无法完整解码、多帧图片和核验后文件变化。
- 流式入口沿用现有错误 header；客户端继续读取固定 code，忽略服务端异常正文。目录导入、非流式导入和手动证据上传也只返回固定提示。
- 权限、错误归属、回执过期和未知 provider/transport 异常继续使用各入口的安全通用提示；不从异常文本、外部 code 字符串或私有地址推导业务错误。即便已知错误的 message 被替换，也只返回固定提示。
- 诊断只含 stage/category/固定 code。文件校验失败属于 `upload`，不会进入 #348 的瞬时 transport 重试；已有两次读取上限、权限重查、完整字节校验和最终事务不变。
- PNG/JPEG 完整解码失败转换为固定图片错误；所有图片签名、多帧、像素和大小限制保留。没有修改 Product Ready、工程事实、人工门禁或模型输出要求。
