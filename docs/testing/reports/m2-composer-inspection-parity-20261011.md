# M2 编辑器检查与实际发布定位对齐

继续原 [#156](https://github.com/ban12-project/F-Trade-Platform/issues/156)。#588 已修复原生 URL 迭代问题并恢复生产只读观察。本轮推进当前编辑器审核，保留具体逐帖授权、媒体接收与自动回执的独立条件。

## 直接核对

生产旧候选配置包含 `openComposerText`。发布程序在 CSS 匹配后用此文本精确筛选，检查器此前却丢弃该字段。因此上次的 19 是原始 CSS 匹配数量，不能据此断言实际发布执行器定位不唯一。

当前生产接管通过短点击打开了空编辑器。背景导航随编辑器开启被隐藏，旧检查器返回身份数量零和未匹配，提前退出；实际发布程序在编辑器存在时核对编辑器内的身份。此差异会阻止取得真实编辑器证据，不能以隐藏背景身份替代当前编辑器身份或把未观察写成通过。

## 修复

- 私有候选读取器保留可选 `openComposerText`，沿用发布执行器的字符串、非空和 200 字符上限；异常输入继续拒绝。该字段不进入返回或审计。
- 检查器沿用相同的精确文本筛选，不在缺失、重复匹配时假装唯一。
- 编辑器关闭时核对页面身份；存在唯一编辑器且有已配置的编辑器身份选择器时，核对该编辑器身份。编辑器重复、身份缺失或不符时拒绝匹配，不能回退到背景导航。背景的隐藏／inert 规则保持。
- 只读程序仍只输出有界计数和布尔／未观察值，不点击、修改正文、上传或发布。候选原字节和日期不是本修改的写入对象。

## 原生验证

初始提交的双架构 [38123089966](https://github.com/ban12-project/F-Trade-Platform/actions/runs/38123089966) 验证了原生 HTTP 文本筛选正反对照，以及实际发布页面程序打开隐藏的合成编辑器后可见的 DOM 变化。测试全输入合成且 network-none；不能用函数返回 true 代替编辑器实际出现。

后续增加背景隐藏／inert、编辑器身份不符／缺失及重复编辑器对照。最终结果以本补充 PR 最后提交的 CI 为准，失败在同一 PR 修复。本机字段校验、Node 回归、Biome 与 TS7 通过；原生环境结果不从普通 Firefox 推导。

## 剩余验收

当前候选仍过期且 textOnly；实际页面／受众与媒体审核、具体文件上传授权、逐帖确认和自动回执继续分别核验。本次代理通过 coda 执行委托审核，不冒充独立工厂签署。真实页面、配置、业务标识和凭据保留在受限本地；GitHub 只记录工程结果。独立入站按用户决定暂缓，网关模型日志按政策 1.1.0 排除且未核验。
