## 交付行为

- 文字、图片和视频确认提交时，在同一数据库事务内尝试登记节点运行与 Sandbox 启动意图。外部启动留在事务外；事务失败同时撤销业务提交与意图。
- 节点锁已被控制器占用时跳过即时预约，已提交的唯一发布任务由原恢复调度接手。不能等待节点锁并同时持有业务锁：控制器采用节点到业务的相反锁顺序，会产生死锁。恢复仍重新检查当前账号、审核范围、项目权限和发布内容；unknown 不重试。
- 登录结果保存本次实际遇到的密码／TOTP／PIN 阶段和有限的 Messenger 观察。空收件箱、看到聊天条目和完整历史恢复分开；旧回执缺失数据继续未知。重复因素、自由文本、冲突重放和非 ready 的历史声明均拒绝。
- 发布列表在服务端把固定失败码映射为可读提示，未知旧字符串与原始失败码不进入客户端数据。发布阶段失败不证明已经点击发布。

## 验证

隔离本机 PostgreSQL 使用全部迁移、真实事务和合成记录；存储只返回合成字节，禁止外部 I/O。新增用例覆盖三种格式的提交／启动回滚、并发去重、忙节点立即返回与恢复调度、诊断隐私。已有社交权限负控 194 场景通过；节点／租约／协议 81 项通过；Facebook 数据库回归覆盖登录与回执重放、当前授权、暂停和人工核对不改写历史 unknown。

Chromium 的登录页面／发布执行器 51 项通过，人工核对表单的诊断显示、客户端校验与未认证拒绝通过。首次本机 dev 运行的地址为 localhost，测试使用 127.0.0.1，Next.js 拒绝开发资源，导致表单未接管而原生提交；改用同一 127.0.0.1 启动地址后复测通过，没有放宽 `allowedDevOrigins` 或关闭编译器。Next.js MCP 编译问题为空，连接浏览器后的运行错误为空。

TypeScript 7、迁移元数据与改动文件 Biome 校验通过。最终提交的完整 CI、原生双架构测试和合并状态以关联 PR 为准。上述证据不等于真实账号接受或发布成功。
