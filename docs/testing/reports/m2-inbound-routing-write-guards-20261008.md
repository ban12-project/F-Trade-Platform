# M2 入站分流当前授权与跳转核验 — 2026-10-08

关联 [#561](https://github.com/ban12-project/F-Trade-Platform/issues/561)，核对基线为 `main@32f58ed7b8d5259221d6abec51c2ca05bf1c1a98`。本轮入站分流相关修复集中为同一 Issue / PR，整批完成本机验证后才执行最终提交的 CI 与部署。

## 已复现的缺口

隔离 PostgreSQL 中，实际 Server Action 的新建销售项目、关联现有项目两种分流请求均已进入会话行等待。在观察到实际数据库等待后撤销原登录会话、将当前用户降为不具销售权限的角色，旧实现仍返回成功、关联会话并各创建一条线索。全程为合成资料，外部调用被禁止，原失败记录保留。

签名浏览器的正常分流还复现了保存后留在任务页的问题：刷新已移除待分流行及弹窗，弹窗中的成功 Effect 未执行预期的线索导航。页面已显示新增线索，但 URL 仍为工作台。这是实际流程失败。负向浏览器探针另有测试定位错误：加载时 Spinner 改变按钮的可访问名称；未执行后续撤权操作的用例不作为授权失败证据。首轮日志及 trace 均保留，中断该轮后修正定位并完整复测，没有增加重试或放宽等待、拒绝、零写入断言。

## 完整修复

- 分流 Action 与领域调用传递并独立校验服务端 actor / session，旧 actor-only 入口拒绝。用户不能通过表单替换该身份。
- 在会话及目标项目等待后，锁定当前用户和所属登录会话，复查销售权限、禁用及过期状态。关联只接受当前 active 销售项目及 owner / editor 成员，项目和成员权限保留到提交。
- 项目、成员、线索、归属关系、会话指针及审计原子提交；最终审计等待期间自然过期会整体回滚，不留下孤立项目或线索。
- 普通业务员和管理员均保留正常分流权限。同一会话并发提交只允许一条线索；原去标识化标题、消息留存、入站去重及停用边界保留。
- Action 仅返回必要的项目 / 线索标识。认证或底层异常使用受控提示；已完成分流、无编辑权或归档等已知提示保留。提交后的刷新失败仍返回实际成功结果。
- 成功导航在提交处理函数中执行，页面刷新移除弹窗后仍进入已保存线索；失败时保留弹窗与目标选择。继续使用现有 shadcn Dialog、Select、Field、Button、Spinner，未引入基础控件或改动编译配置。
