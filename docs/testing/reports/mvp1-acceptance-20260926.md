### 保留的失败及修正

1. 初次旧 pnpm 启动器无法获取 `@pnpm/linux-x64@12.3.4`。随后确认 `pnpm@12.3.4` 本身可用，使用同版本官方包恢复安装；不能据初始错误宣称锁定版本不存在。
2. 初次测试 runner 的 PATH 覆盖使子进程使用 Node 22，相关结果不作为正式基线。显式 Node 24 路径复跑后浏览器模块加载错误消失。
3. 初次 Chromium 批次因缺少 `libnspr4.so` 无法启动；解压当前 Ubuntu 依赖到仓库外并设置局部动态库路径后完整复跑通过。未修改生产镜像或测试断言。
4. 初次 FFmpeg 类测试缺少执行文件；配置实际二进制后分别重新通过，未将模拟媒体 probe 当真实编码结果。
5. 视频创作夹具在 Node 24 独立复现失败，修复及回归如上。
6. Python venv 缺少 ensurepip；使用仓库外 pip 和 requirements-dev 安装验证依赖。broker 消融首次缺少专用数据库变量而拒绝启动；提供独立本机测试库后通过。仓库总校验首次也选中旧 pnpm 启动器，改用同版本工具路径后另行复验。均为执行准备错误，不是业务缺陷。
7. 首次最终构建被新摘要文件的 JSON 排版检查拒绝；仅格式化该文件后完整构建通过。
