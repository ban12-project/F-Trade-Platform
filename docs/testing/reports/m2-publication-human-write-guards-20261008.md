## 实际发现

隔离 PostgreSQL 中，实际 Server Action 已通过登录入口，随后等待被占用的内容或渠道行。在确认数据库真实等待后撤销会话并降权，旧实现仍分别创建一条发布及任务、恢复一个已暂停渠道；提交后的派发回调被拦截，外部调用为零。原失败记录保留。首次探针的两个 fixture 缺少必填时间及暂停理由，修正后才记录上述实际复现；它们不算实现失败。

继续核对发现，发布、素材确认、手动未知结果核对和账号控制的领域边界使用 actor ID，无法独立证明当前会话；部分管理员校验发生在来源等待前。实际签名回调探针还证明，连接记录等待后沿用旧时间会接受已自然过期会话的心跳，并写入回执。另一个实际合成探针证明，通用视频确认会创建发布任务，却没有 `facebook_publication_manifest`，与下游需要的完整素材确认不匹配。

## 一批修复

- 人工文本、图片和视频确认、文字 / 视频 unknown 核对、渠道启用 / 暂停 / 恢复及账号凭据 / 连接 / 恢复统一携带服务端取得的 actor / session；项目操作还必须匹配当前 project。旧 actor-only 调用拒绝。
- 在来源、渠道、节点或连接等待后复核当前权限、禁用状态、会话归属与期限；当前项目为营销项目，发布要求 active，拥有者 / 编辑者及自有内容关系被保留到事务结束。历史效果核对允许 archived，但不授予新的发布权限。
- 事务内锁定用户和会话并在最终审计后再次检查自然过期；发布、任务、素材清单、凭据 / 连接状态与审计一起提交或一起回滚。渠道控制在读取状态前串行化同一账户，包括首次创建记录。
- 素材确认保留版本、摘要、来源及私有视频字节校验；视频私有回读后再次检查当前授权，图片权利按等待后的时间检查。已取得的当前产品、素材、来源证据与 Gate 行保持稳定，渠道范围在最终提交前再次核对。
- 通用发布入口只接受文字。已批准视频的页面指向现有素材发布流程；图片 / 视频向通用领域及 Action 提交均不产生无清单任务。素材确认仍须配置的账号拥有者、当前审核权限、完整预览与逐次确认。
- 签名 Gateway 回调沿用原应用会话的当前授权，在实际连接等待后及回执 / 状态写入后复查应用与连接有效期；六种操作的过期拒绝不返回凭据、状态或可重放回执。
- Action 的成功结果只返回必要标识或授权连接票据字段；认证服务或数据库失败返回受控提示，不泄露原始错误。正常文字业务员仍可确认已独立批准的内容。

Gate 01、工程事实来源、平台 / 账号限制和素材政策没有被合成测试补齐；不把用户当前测试审核委托扩展为真实业务授权。

本轮只使用明确标记的合成资料、字节和签名测试会话；数据库内的素材 metadata、批准和票据只证明授权与事务行为，不证明真实渲染、版权、工厂事实或账号平台接受。视频 Blob 验证由受控流适配；生产派发回调、真实账号与外部网络均被阻止。没有执行真实发布、客户消息、报价 / 交期审批或已暂停的 Sandbox / 出口操作。
