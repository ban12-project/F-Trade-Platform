# MiMo V2.6 全系列可访问性与验收对比 · 2026-09-22

关联 #369 / #392。用户要求新发布的 Xiaomi MiMo 模型各跑一轮并汇总。本轮按前述协议，每个可访问模型运行 20 个固定 synthetic 样本 × 3 次，共 60 次；没有将“每个一次”解释为每样本仅一次。

## 模型与访问验证

[官方发布记录](https://mimo.mi.com/docs/zh-CN/updates/model)列出 2026-09-22 发布的 `mimo-v2.6-pro`、`mimo-v2.6-flash`、`mimo-v2.6-pro-ultraspeed`。[模型列表](https://mimo.mi.com/docs/zh-CN/quick-start/summary/model)将 Ultraspeed 标记为定制服务。搜索摘要仍残留旧版本内容，本次以打开后的官方页面和实际 API 返回为准。

沿用获授权的 `.env` 中 `MIMO_API_KEY`，调用官方 Token Plan China 端点。模型列表返回 Pro 和 Flash。两者分别通过 128×128 红色 PNG 的 Base64 图片烟测，HTTP 200，响应模型 ID 与请求一致，回答 Red，各记录 16 image tokens。

Ultraspeed 同样尝试了图片烟测，API 返回 HTTP 400、`Not supported model mimo-v2.6-pro-ultraspeed`。因此未执行其 60 次产品评测，标记为不可访问，不能记为 0/60 或模型质量失败。补测需要可访问该定制服务的接口与凭据；没有改用其他模型冒充。

## 方法与可比性

使用现有生产运行器、prompt 1.0.11 和冻结 verifier。重新生成已清理的临时数据集后，验证 20 个 expectation hash 与 Luna、MiMo V2.5、Kimi K3 旧批次完全一致。相关生产 Agent、提示词、样本、评分器与 Luna 代码提交相比无差异。没有调整提示词、字段类型指导、输出格式或包装期望。

每模型四路并发，两模型同时执行，合计最多八路；每次进程上限 190 秒。未启用应用层修复重试，AI SDK 默认传输重试保持不变；不覆盖供应商默认思考参数。每次结果保留，不重跑替换失败。

只使用合成数据及指定模型凭据，没有发送真实工厂/客户资料或应用数据库凭据。正式样本的图片仍是无产品信息的 1×1 PNG，红色图片烟测单独计数。图片链路通过不代表产品视觉识别或工程事实核验。

这是本机生产 runner 的模型验收，没有执行 Harbor 容器批次，也没有修复此前 Podman 环境障碍。
