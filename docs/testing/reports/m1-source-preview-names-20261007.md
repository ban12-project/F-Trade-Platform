# M1 产品来源预览的原文件识别 — 2026-10-07

关联 [#525](https://github.com/ban12-project/F-Trade-Platform/issues/525) 与 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)。本轮补齐产品审核来源预览的文件识别，不改变工程事实或正式试点验收条件。

## 问题与修复

资料上传后，证据标签按类型保存为 `uploaded:pdf`、`uploaded:csv`。资料选择器已读取可核验的上传原文件名，但来源预览仍显示通用标签，审核者难以区分同类资料。

来源预览现在仅在回执的私有文件路径、证据 ID、上传者 ID 和人工上传类型全部匹配时使用原文件名。旧资料或回执错配仍显示原证据标签。授权范围继续限定于当前项目与产品关联的证据；返回页面的五项数据字段保持原契约。

## 验证证据

- 使用真实回执签发、字节核验和持久化认领流程创建合成来源。修复前，预览实际返回 `uploaded:csv`，原文件名断言失败；修复后通过。
- 两个文件包含相同字节但原文件名不同，保留独立证据与预览名称；未关联当前项目的自有上传不出现在预览中。
- 路径、证据 ID、上传者错配及非人工来源均回退标签；已认领来源的文件名不会随签名令牌过期而丢失；旧来源保留原标签。
- 非成员和封禁用户无法读取预览；私有字节、MIME、完整摘要校验和读取期间撤销权限的既有回归通过。上传回执整套回归通过。
- 实际登录产品审核页面显示两份原文件名及独立字段关联，刷新后保留；空白浏览器会话请求原件返回 403 且禁止共享缓存。测试显式清空匿名会话的继承存储，保留最初测试上下文错误的本地日志。
- TypeScript 与改动文件格式检查通过。Next.js 开发页面及 React 来源组件验证通过；完整 CI 最终结果记录在关联 PR。

仅使用本地隔离数据库与合成资料，外部文件读取以合成字节替代。未调用付费模型、添加真实工厂事实或写入生产业务记录。原始调试记录和会话仅保存在本地忽略目录。
