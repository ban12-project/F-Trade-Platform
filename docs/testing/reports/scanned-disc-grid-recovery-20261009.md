# 扫描盘片表头、外框与序号恢复 — 2026-10-09

在原 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)／[#5](https://github.com/ban12-project/F-Trade-Platform/issues/5) 内接续[上一检查点](scanned-disc-source-columns-20261009.md)。上一镜像仅有十个盘片槽位获得八列结构，115 个非空原格逐字匹配 50 个，序号格均未恢复。

## 修复和拒绝条件

表头尾字或括号说明无法复读时，单独达到原置信度门槛的主标签可以保留其原字面值；不补写 TYPE、单位或元组含义。主标签自身不可读时仍退回核心编号／OEM 两列。

较强的远端页面边框曾使较淡的真实外框无法进入候选。外框现在使用独立的浅灰像素投影及原有最低可见度，位置必须在完整表头文字之外；内部列与各格上下行界继续使用原像素规则。相邻双线无法区分、边界过宽、跨界文字、低置信度或超时继续拒绝。序号和车型不通过编号、行顺序或常见品牌推算。

先前候选版本虽恢复序号，却把重复灰色字形竖笔画错判为第八列外框，截短了十个既有车型值；实际原件对照捕获了该回退，该镜像未配置到生产。新增回归在修复前因错误裁剪宽度失败；修复后通过。远端强边框、弱／浅外框、近邻双线、不可读主标签／尾字及每格独有像素标记同时验证，不以降低 OCR 置信度换取通过。

## 实际镜像和冻结来源对照

本机实际 Ubuntu 镜像及云端两 vCPU、deny-all 临时 Sandbox 通过原生／扫描／空页、套件和盘片三套禁网回归。最终云镜像摘要为 `sha256:492d4b379dd1b76fd71f288869d7b625d3759e2ecbafbcea479471b574c0f76e`，四份转换模块摘要与本 PR 源码一致；合成 H264／AAC 编码通过。临时云实例及其快照已删除。

仍按生产转换入口的每文档 120 秒、每页 60 秒额外盘片预算读取原件物理第 7／8 页，保留原 OCR 和物理页标记。冻结核心清单、20 槽位期望、两份原件摘要及各槽位自身物理页证据保持一致；没有重写期望来消除失败。
