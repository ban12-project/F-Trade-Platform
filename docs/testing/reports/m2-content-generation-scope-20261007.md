# M2 内容生成项目授权验收（2026-10-07）

关联研发风险：#527，M2 内容发布闭环。范围为内容初稿生成的项目授权与生成期间的权限／事实变化。

## 已确认缺陷与修复

原 Server Action 允许省略 `projectId`，缺省时跳过项目授权并读取全局 Ready 产品。隔离 PostgreSQL 回归中，普通 editor 省略项目并提交其他项目的合成产品 ID，原 Action 返回 `success`，与预期拒绝不符。该结果确认了服务端授权缺口；未检查生产利用情况，也未访问真实客户或工厂资料。

生成请求现在使用客户端与服务端共用的 Zod schema 强制项目标识。服务端独立核对数据库中的账号权限和停用状态、有效营销项目写权限、指定产品的项目关联、Ready 状态及已核验字段。拒绝发生在读取模型配置和模型请求之前。

模型完成后重新核对会话及请求者、当前账号、项目权限和同一组事实。会话撤销、成员撤权、项目归档、账号停用、Ready 撤销或所选事实变化时，不返回旧初稿。现有创建待审内容、人工确认及发布门禁继续生效。

## 验证证据

- 新增 PostgreSQL 回归使用真实 Action 边界、Zod、项目授权和产品查询；只替换会话传输、模型配置与执行。15 种拒绝场景均未读取模型配置或请求模型；合法 owner/editor 成功且仅传入授权产品事实；6 种生成期间变化均丢弃结果。
- 本地数据库限定为 `127.0.0.1` 的独立 `f_trade_stream_test`。所有产品、用户与项目均为明确标记的合成数据；没有付费模型请求或生产写入。
- 已编译页面的 14 项浏览器回归通过：正常生成、五个草稿字段的人工编辑保护、产品／事实／类型／目标／客户变化、失败重试及生成与提交互斥。页面测试替换 Action 响应，不代替上述服务端数据库测试。
- 自有 Next.js 16.3.8 / Turbopack 开发实例启用 Cache Components 和两个 React Compiler 配置。运行中的表单由 React DevTools 核对；编译与运行错误由 Next.js 自检核对。TypeScript 校验和变更文件格式检查通过。
- 新增数据库安全回归已纳入现有 PostgreSQL CI 作业。PR 最终提交的完整 CI 结果在 PR 交付记录中核对。
