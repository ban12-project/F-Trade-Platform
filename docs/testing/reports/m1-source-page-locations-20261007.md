# M1 产品审核来源页码与记录定位（2026-10-07）

关联 [#532](https://github.com/ban12-project/F-Trade-Platform/issues/532)、[#48](https://github.com/ban12-project/F-Trade-Platform/issues/48) 与 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)。本轮补齐审核页面，保留此前已验证的目录解析、物理页与空页追溯结果。

## 已确认问题及修复

实际生成三页合成 PDF：第一页面标识、第二页空白、第三页包含明确标记的测试产品名称和编号。原生转换、目录候选发现、上传回执认领、摘要核对及 PostgreSQL 记录均保留第三页的字段引用；原预览返回的位置为 `undefined`，与预期的物理页 3、解析记录行 8 不符。该失败保留在本地私有日志。

审核预览现在返回每个匹配字段的来源位置。目录导入证据 ID、原件摘要、候选保留位置及字段精确引用必须一致；相同字节的另一份上传不能借用当前目录记录的摘录或位置。页码和行号不从任意引用前缀或模型文字中猜测。

PDF 字段显示原件物理页及解析文本记录行，并经既有私有原件接口提供 `#page=N` 链接。CSV 显示解析文本记录行，不生成 PDF 页码入口。整份原件入口、旧来源及无法定位的字段继续保留。解析行号明确标为“解析文本”，不冒充 PDF 中的印刷行号或 CSV 原始行号。

原件入口采用已有 `LinkButton`，保持链接语义和键盘操作；私有二进制资源关闭预取。身份、项目／产品／证据授权和完整字节校验保持原实现，不新增文件接口或公开地址。页码片段仅由浏览器读取，不作为服务器授权输入。[Chromium 官方参数解析实现](https://chromium.googlesource.com/chromium/src/+/HEAD/chrome/browser/resources/pdf/open_pdf_params_parser.ts)支持从 URL 片段读取物理页参数；[shadcn/ui 官方链接用法](https://ui.shadcn.com/docs/components/base/button#as-link)要求保持链接语义。

## 验证

- 新增隔离 PostgreSQL 回归执行实际 PDF／CSV 原生转换、候选发现、回执认领与私有字节摘要核验；PDF 第三页及 CSV 解析记录行正确。数据库候选由测试夹具持久化，没有调用模型或运行完整目录工作流。
- 页码、行号、保留来源摘要、证据位置引用及导入证据 ID 错配均不返回假定位；完整引用未匹配的字段和整份来源引用没有被自动指定页码。同字节独立上传不复用摘录或位置。非成员及停用账号不能读取。
- 既有来源预览 PostgreSQL 回归通过，覆盖原文件名、回执错配回退、旧摘录、页面最小 DTO、只读成员、非成员／封禁拒绝、字节／MIME 完整性及读取期间撤权。
- 17 项专项页面回归通过，包括三个新增位置／回退／键盘导航检查及 14 个既有 M1/M2 编辑回归。新增页面测试只替换文件响应，验证浏览器新窗口带页码片段、服务器请求不带片段；不代替数据库授权检查。
- 本地有界 Chrome 原生 PDF 检查通过。通过实际字段链接打开三页合成 PDF，保留与正式文件接口一致的私有缓存和安全响应头；截图可见阅读器页码 `3 / 3`、第三页测试文字以及空白第二页缩略图。此项替换二进制响应，不声称已回读生产 Blob。
- TypeScript、改动文件格式及完整仓库校验通过。本地首次静态检查读到过期增量状态；保留原失败，无缓存检查及重建项目根增量缓存后的默认检查均通过，未清理 `.next` 或修改检查配置。运行中的 Next.js 16.3.8 / Turbopack 编译和运行错误为空；React 来源组件已核对。Cache Components、两个 React Compiler 配置和 TypeScript CLI 保持启用。
- 新增原生转换／数据库回归纳入 PostgreSQL CI；该作业明确配置 Python 3.12 并复用既有转换依赖。最终提交完整 CI 结果记录在关联 PR。
