# 产品最终事实审核与 OCR 效率检查 — 2026-10-09

接续原 [#268](https://github.com/ban12-project/F-Trade-Platform/issues/268)／[#5](https://github.com/ban12-project/F-Trade-Platform/issues/5)，落实用户本次明确调整的验收标准，见 [ADR 0010](../../decisions/0010-product-final-fact-acceptance.md) 和[执行矩阵](../product-agent-acceptance.md)。来源选择 #6 的既有授权与 A–D 各五个范围不变。

## 最终事实决定就绪

自动识别率、OE／车型抽取诊断、缺失识别率、耗时和修订轮次不再单独阻断最终已审核的产品。当前关键字段必须完整、所有填写事实经来源核实、有字段级证据且 Gate 01 批准，才成为 ProductReady。关键工程事实缺失或未确认仍阻断；C/D 负例正确阻断可通过流程验收，但该产品不就绪。

新验收结果显式引用政策 v2.0.0、产品版本、最终审核人／时间／记录、来源清单、证据和纠正审计。未版本化历史结果继续采用 v1 规则，原失败记录不改为通过。来源期望录入错误仅以保留旧值、原件、理由和审核者的新版本勘误修正。

发现的实现缺口是人工修订审计原先只有数量，没有字段改前、改后内容。现将两个修订入口的字段值、证据变化、字段删除、补录和来源／版本差异保存到私有只追加审计；与产品更新、工作流事件和新的待审核记录同事务提交。执行者和时间由服务端保存，不将业务事实返回客户端或写入 GitHub。旧历史没有差异时不伪造补记。

合成回归允许低自动识别率且修订三轮后取得有效最终审核；拒绝高识别率但缺关键事实、缺来源、缺审核或缺修改记录的就绪声明。已覆盖修改值、只变证据、删除字段、补录布尔否值及来源变化；数据库回归覆盖无权、改变来源、并发争抢、图片审核及日志更新／删除拒绝。

## 可复用 OCR 模型的效率改进

在独立 Linux 子进程复用已经验证的 Tesseract 5.3.4 英语模型，避免每格重复加载。整页和原格定位、原始文字、置信度及来源规则沿用原实现；缺库、非英语或未经验证版本回到原 CLI。子进程崩溃和超时受到隔离，页／文档预算及最多五秒的单格读取不增加。某个小格不可读时只记录该格失败，随后继续使用健康会话。

API 使用依据为官方 [C API](https://raw.githubusercontent.com/tesseract-ocr/tesseract/5.3.4/include/tesseract/capi.h) 和[示例](https://tesseract-ocr.github.io/tessdoc/APIExample.html)。没有追加语言模型、字符替换、原件字典或单位推断。尺寸字形试验在独立合成材料中产生字面误读，已保留失败诊断并移除该路径；多次 OCR 一致不能证明工程事实正确。

受控原格的 60 次对照中，可复用会话与 CLI 的全部文字、置信度和坐标一致。该读取阶段累计耗时为 2.64 秒与 11.92 秒；这是局部测量，不代表完整文档的统一加速比例。两 vCPU 禁网本机原件第 7／8 页实际处理为 51.54 秒。

最终云镜像 `sha256:b5c429f2ff723a25eeb41bc580392d02cf3d551b08bfea28f18796fe8fe5cf3f` 已在两 vCPU、deny-all 的临时 Sandbox 验证五转换模块和既有固定英语模型摘要、三套文档／套件／盘片回归及合成 H264／AAC 编码。临时实例和快照均删除。

同一来源的 15 个盘片槽位各恢复自己的物理页编号及八列，第 7／8 页保持 33／25 行。115 个非空原格仍为 85 格逐字匹配、19 格未读出、11 格字面差异；此前六类可读字段和十组自身 OE 完整保留。尺寸 OCR 的剩余错误按新政策作为效率诊断，不能直接作为最终工程事实。私有来源清单新增一处有原件支持的录入勘误；旧清单和旧运行结果保留，新版本未提高上述匹配数。

## 交付范围

本次交付是验收政策、可追溯修订和 OCR 效率改进；不会仅因政策调整宣布整个 M1／M2 或既有 20 槽位最终审核通过。新的 20 槽位最终审核仍须逐项回查实际证据、审批和产品状态；其他发布、入站、RFQ、到期删除及托管副本验收沿用其原范围。

最终 CI、squash 来源、正式部署及正常页面复验追加在同一 PR 和原 Issues。真实原件、逐 SKU 值、修订明细与试验失败日志保持私有。本次委托审核如实记录为 Agent 使用授权账户，不冒充独立工厂签章。
