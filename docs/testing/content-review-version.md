# 内容审核版本绑定

关联 #297、#26。所有执行数据均为隔离 PostgreSQL 中的纯合成记录和预置测试会话。

基线 `bab9365` 的双会话浏览器回归复现了旧页面审批问题：一份文案从版本 1 被退回并
修订到版本 3 后，仍停留在版本 1 的会话提交批准，Server Action 返回成功。基线执行：
https://github.com/ban12-project/F-Trade-Platform/actions/runs/33958343908/job/101285637983 。

修复要求客户端与服务端共用 `reviewedVersion` 和 `approvalId` 校验。内容详情返回
实际版本，审核表单展示它；记录、版本或审批请求变化时重建表单。服务端锁定聚合后
比较版本，再核对当前待审请求 ID，在任何写入前拒绝旧输入。

回归覆盖：

- 两个独立浏览器上下文，旧页面不能批准后续修订。
- 当前版本配错误审批 ID 仍被拒绝，独立于版本检查。
- 拒绝后聚合状态、版本、待审请求、事件和审计均不变。
- 切换两条待审内容后，批准只作用于正在显示的记录，原记录仍待审。
- 当前页面仍能完成正常退回、修订和批准；缺失、非法或超出安全整数范围的版本被拒绝。

页面渲染和隐藏字段都不是授权边界；Server Action 继续独立认证、权限检查和校验。
本回归不代表真实工厂审核或外部发布，旧客户端缺少绑定字段时必须刷新后再提交。
