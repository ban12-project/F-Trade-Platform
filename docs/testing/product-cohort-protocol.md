# Product Agent A–D 测试协议

本协议在真实 SKU 获得授权前使用 synthetic 数据验证流程，不用于证明真实产品识别准确率。可执行清单位于 `data/fixtures/product-cohort.synthetic.json`。

| 组别 | 数据 | 实物图 | 预期结果 | 必需人工动作 |
|---|---|---|---|---|
| A | 完整、有 OE 和字段证据 | 有 | 自动检查无阻断项，仍需 Gate 01 | 核对事实、图片与产品一致，记录人/时间/证据 |
| B | 完整、有 OE 和字段证据 | 无 | 数据可送审；图片缺失不得由生成图“补证” | 选择真实图片或明确标注的无实物图内容，记录 Gate 01 |
| C | 无 OE，有应用、品牌和车型，尚待确认 | 有 | 保持 `review_required`，列出 `oe_numbers_or_verified_application` | 人工核验完整应用身份和图片一致性，再决定批准或退回 |
| D | 无 OE，有应用、品牌和车型，尚待确认 | 无 | 保持 `review_required`；数据和图片问题独立处理 | 核验完整应用身份；选择真实图片或明确标注的无实物图内容 |

## 图片安全边界

- 图片来源引用与输入字节必须一一对应：拒绝重复或空引用、重复图片输入及缺少对应字节。
  `scripts/test-product-source-images.ts` 使用合成像素回归校验此绑定；它不证明图片与实物一致。
- 真实产品图片作为产品视觉证据时，必须保存在 Private Blob 并关联证据元数据。
- AI 生成或编辑仅可用于背景、排版，或清楚标注为 illustration 的营销示意。
- 生成图不能成为 OE、车型、花键、孔位、尺寸、材料或零件数量的结构证据。
- 无图路径不得从同类商品或参数推断产品外形；获取不到真实图片时，应使用文字/图形排版或等待人工提供素材。
- 任何处理不得改变花键、孔位、尺寸比例、材料观感或套件零件数量；无法确认一致性时 Gate 01 必须拒绝。
- 对图像型 PDF 启用本地 OCR 时，OCR 文本仅是待核对的非结构化来源；识别错误、缺字或版面错位不得成为
  工程事实。审核人仍须在原始 PDF 页视觉核验每项已填写事实与字段级证据。

## 执行与记录

`pnpm test:product-catalog-entry` 包含 `scripts/test-product-cohorts.ts`，在仓库 CI 中执行四组领域校验：批准、退回后使用 MOCK OE 与独立字段证据修订再批准，以及拒绝只有车型或缺失字段证据的记录。C/D 当前夹具具有完整应用身份；模拟 Gate 01 可以确认该身份后通过，不强制补 OE。测试中的 human 角色和确认记录均为模拟，不代表实际人工批准。

此回归不读取图片，不覆盖上传、浏览器或真实图片一致性。A/C 的图片分组标签只是测试矩阵元数据，不能据此宣布 A–D 实物图验收通过。

每组至少执行一次批准路径和一次拒绝/修订路径。测试记录只保存 synthetic 标识、预期/实际阻断项、人工动作类型、耗时和结果；真实源文件、客户信息和未经授权产品数据不得进入 GitHub。失败必须新建研发 Issue，并引用测试运行标识，不能修改预期值来掩盖失败。
