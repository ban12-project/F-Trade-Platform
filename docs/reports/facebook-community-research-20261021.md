# 如何将 Facebook 养号经验转为外贸社区参与依据

本文供外贸运营与研发评审 Facebook 社区流程。研究优先采用 Meta 公开说明，再对照外贸交流材料；没有找到足以验证“养若干天即可安全自动化”的证据。保留流程请查看[社区筛选、内容与询盘流程](../architecture/facebook-community-playwright-plan.md)，新增线上动作由 [Decision #623](https://github.com/ban12-project/F-Trade-Platform/issues/623) 跟踪。

## 研究计划与证据分级

本页的目标是判断哪些经验值得保留，哪些主张不能成为执行规则。内容依次覆盖官方依据、社区流程、冲突与待核实项。

研究范围及未决问题如下：

- **受众**：外贸运营、渠道负责人、自动化实现者
- **范围**：账号准备、行业社区筛选、群内交流、询盘承接
- **事实**：本次取得的公开正文或已提交仓库契约支持的陈述
- **社区主张**：作者经验；不代表 Meta 规则或因果验证
- **项目建议**：结合现有范围提出的设计；不代表已实现能力
- **未知**：现行条款全文、具体群规、平台自动化许可、真实账号效果

检索日期为 2026-10-21（Asia/Shanghai）。本次没有登录真实账号、加入社区或联系成员，也没有保存成员资料或帖子正文。

## 哪些步骤可借鉴，哪些结论应拒绝

建议把“提高账号权重”的目标改为“完成真实身份、社区规则与内容审批检查”。这属于项目设计建议，不能保证账号不受限制。

| 原始做法 | 判断 | 项目处理 |
| --- | --- | --- |
| 完善身份与业务介绍 | 可保留准备任务 | 使用真实获授权资料，区分个人身份与企业 Page；不编造生活经历 |
| 先观察再参与 | 可保留核实步骤 | 阅读群规并确认讨论相关性；不用累计浏览时长判定账号成熟 |
| 按行业与地区找社区 | 可保留筛选方法 | 优先离合器、汽配售后、经销商与进口商讨论；候选名单由人工核实 |
| 少复制、多提供相关回答 | 与 M2、M3 方向一致 | 围绕实际问题写回答；工程事实绑定工厂来源 |
| 定时点赞、关注、加好友以提高可信度 | 效果未证实且可能制造互动 | 不转成自动化任务或增长指标 |
| 养号数周后扩大营销 | 不能证明安全或权限 | 以规则、授权和逐次审批判断；禁止按账号年龄自动解锁 |
| 从成员列表开发或主动私信 | 超出当前范围 | 不采集成员名单；仍只承接对方主动发起的私信 |
