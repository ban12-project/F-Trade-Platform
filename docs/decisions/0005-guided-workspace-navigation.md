# ADR 0005：工作台与项目采用线性引导流程

- 状态：Accepted
- 日期：2026-09-04
- 关联：Issue #256
- 取代：ADR 0003 中“画布作为唯一入口”和“业务操作依赖可编辑节点图”的部分；ADR 0003 的角色、权限、事务和 Human Gate 边界继续有效

## 背景

F-Trade 的真实业务顺序由领域状态机决定：产品事实核验后才能生成内容，内容／视频审核后才能发布；销售侧则依次处理线索、RFQ、人工报价、跟进、交期确认和商机认定。项目画布只保存节点位置和关系，不保存产品事实、报价、交期、发布结果或审批决定。

把画布设为默认入口后，用户必须先理解缩放、节点、检查器、布局保存和“整理画布”模式，才能执行本来已经有明确顺序的任务。这增加了交互模型，却没有增加业务表达能力。

同类工具采用更直接的分层方式：

- [MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo) 把主题输入、脚本、素材匹配、字幕／音乐和成片组织为自动化主路径。
- [ViGenAiR](https://github.com/google-marketing-solutions/vigenair) 先分析素材和片段，再让用户预览变体、调整片段、进入渲染队列并审核输出。
- [Scene Machine](https://github.com/google-marketing-solutions/scene-machine) 明确划分 Setup、Storyboard、Composition 和 Output 四个阶段。
- [OpenCut](https://github.com/OpenCut-app/OpenCut) 把时间线、脚本和渲染能力留在专门的视频编辑器边界内，而不是用编辑器承载业务项目导航。

这些项目的共同点不是界面样式，而是先暴露用户目标和下一动作；只有需要精细媒体控制时才进入编辑器。

## 决策

### 1. 全局工作台

`/workspace` 默认展示：

1. 尚未分流的入站消息；
2. 跨项目下一动作；
3. 待审批和到期跟进；
4. 项目／线索 Pipeline。

项目总画布不再是生产入口，也不再出现在主导航中。

### 2. 项目工作区

`/workspace/[projectId]` 默认使用固定、可深链接的线性步骤：

- 营销项目：产品资料 → 营销内容 → 营销视频 → 发布。
- 销售项目：客户线索 → 需求确认 → 报价 → 跟进 → 交期 → 商机。

每个步骤只呈现该阶段的说明、下一动作和业务记录。待办链接直接定位到步骤和记录，不再依赖 `view=records`；旧查询参数仍被忽略并兼容。

### 3. 视频编辑器

营销视频继续使用独立的 `/workspace/[projectId]/video` 编辑器。素材选择、片段排序、时长、字幕、预览、渲染和成片审核保留在这个连续编辑上下文中；完成后返回项目的“营销视频”步骤。


### 4. 画布迁移

2026-09-04，Issue #258 完成破坏性清理：

- 删除项目总画布、项目节点画布、缩放／拖拽控件和测试专用画布路由。
- 删除 `workspace_canvas_document` 表、保存 Action、布局契约和乐观 revision 控制。
- 删除 `@xyflow/react`、`elkjs` 及对应全局样式。
- 项目创建和入站分流不再生成布局记录；历史项目直接从 `workspace_project` 加载。
- `?view=flow` 诊断入口已经移除，避免形成第二套导航模型。
- 个人 `video_canvas_document` 属于另一套遗留视频实验，仍须独立完成调用方和数据审计，不在本次迁移中删除。

### 5. 安全与领域边界

本决策不改变 Product、Content、RFQ、Quotation 或 Workflow 契约，不改变 owner/editor/viewer 权限，不绕过 Gate 01、Gate 02、Gate 03、逐帖发布确认或外部回执要求。

## 后果

- 用户从“我现在要处理什么”进入业务，而不是先学习画布操作。
- 项目 URL 与业务步骤一一对应，更适合待办、通知、浏览器返回和移动端使用。
- 视频编辑仍有足够的专用编辑空间，同时不会污染项目导航。
- 项目画布代码、持久化和依赖已清理，仓库只保留线性工作流与专用视频编辑器。
