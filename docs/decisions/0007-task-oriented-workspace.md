# ADR 0007：以业务任务与对象组织工作区

- 状态：Accepted（方向已确认，按批次实现）
- 日期：2026-09-19
- 关联：Decision #394；第一批 #395
- 部分取代：ADR 0005 的固定线性阶段作为主要导航的决策；领域权限、证据与人工审核边界继续有效

## 问题

用户进入应用后无法稳定判断起点、阻塞原因和下一动作。代码审查与合成页面检查确认：项目摘要、默认入口与任务链接独立推断阶段；待确认商机会在目标页被过滤；部分带对象 ID 的链接只打开整个阶段。固定的产品、内容、视频、发布步骤还会暗示视频是所有发布的必经前置。

## 决策

1. 主导航逐步改为今日任务、产品资料、内容与发布、客户与询盘；设置按权限呈现。
2. 项目保留归属、成员权限和来源关系。跨项目列表只汇总当前用户有权限访问的记录，不改变现有数据授权边界。
3. 从领域状态派生一份任务读模型，统一解释对象、阻塞原因、处理角色、主要动作及目标 URL。任务不成为另一套可写业务状态机。
4. 区分我可处理、等待他人、系统处理中、需要排查。尚未开始、等待中、已完成有不同的空状态。
5. 任务直接定位具体对象。无法访问或不存在的目标显示返回入口，不能静默改选其他记录。
6. 完整编辑占据主要工作区；来源、历史和相关对象作为辅助信息。视频仍使用独立编辑器，并作为可选内容形式。
7. 销售工作保持客户上下文。跟进是持续活动，交期确认按需发起，商机是人工认定结果。
8. 沿用已有 shadcn/ui、Server Actions、共享 Zod schema、Cache Components、React Compiler 和 TypeScript 7。每次写入仍须重新认证、授权及校验。

## 交付顺序与状态

- [ ] 批次 0：任务目标、候选商机与销售默认入口修复（#395）。
- [ ] 批次 1：统一任务规则、优先级、权限呈现、修订与等待状态。
- [ ] 批次 2：全局外壳、首页、空状态及稳定对象 URL。
- [ ] 批次 3：产品导入、核实、图文制作、审核和发布结果的完整旅程。
- [ ] 批次 4：客户会话、需求、人工报价、跟进与商机。
- [ ] 批次 5：可选视频上下文、旧入口清理与整体回归。

每批独立 Issue → 分支 → PR → CI → squash merge。完成状态以合并的 PR 和验收证据为准。

## 验收

必须覆盖真实路由和数据库中的合成记录，不能只验证单个面板渲染。重点场景：首次进入、缺少来源、退回修订、无审批权限、多记录选择、旧链接、刷新/返回、未保存保护、新线索、待审核报价、HOT 候选、发布结果不确定、桌面和窄屏。

不得因减少交互步骤而绕过工程事实核实、正式报价/交期人工确认、审核版本校验、成员隔离或平台回执。生产渠道资格、真实资料授权和真实用户试用需要各自证据，不能由合成验收推断通过。
