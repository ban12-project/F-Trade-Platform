# ADR 0007：营销视频保留期与责任人

- 状态：Accepted（业务决定）；到期执行机制尚未交付
- 版本：1.0.0
- 日期：2026-10-09
- 原 Issue：[#122](https://github.com/ban12-project/F-Trade-Platform/issues/122)
- 结构化政策：[marketing-video-release-policy.json](../../config/marketing-video-release-policy.json)

## 决定来源

项目方在本次会话表示“M2 的保留期和负责人问题已确认”，随后明确委托“你帮我确认即可”。Agent 据此完成政策审核并选择以下首期值，未将未提供的天数写成项目方此前已指定的数值。生产账号设置实际显示 `coda` 与管理员角色；不在 GitHub 保存邮箱、会话、凭据或业务对象标识。

业务、访问、事实与素材权利审核、逐帖发布确认以及剪辑／渲染额度责任均由 `coda` 承担。本次委托允许 Agent 执行本次审核，操作记录仍须注明 Agent 执行者；此委托不是未来持续代批、独立工厂人员签字或某条帖子发布授权。后续更换负责人须更新政策版本，并通过应用当前认证与项目权限检查。

## 保留与访问

视频工作副本、提示词、AI 剪辑处理输出和私有成片按各对象首次创建的 UTC 时间保留 **90 天**。读取、下载或修改不延长原对象期限；新对象按自身创建时间计算，不能通过复制过期资料续期。权利提前到期、撤回授权或删除要求优先于 90 天期限。该期限是本次委托下独立作出的首期决定，不从 DM 正文的 30 天规则推导。

到期应停止预览、下载、再处理与新发布，并清理对应私有字节、提示词及处理内容；`coda` 负责检查执行结果及失败重试。审核轨迹只保留追溯所需的标识、哈希、决定和政策版本，不保留过期媒体、提示词或供应商原始响应。延期须在到期前由责任人记录具体范围、原因和新期限，更新政策；当前首期没有自动延期。

原始工厂资料与来源／权利证据不属于视频工作副本，不得因本政策批量删除。外部平台上的已发布副本和用户自行下载的副本也不在应用的自动清理范围；如需撤回发布，另走原帖的人工撤回流程。不能承诺从所有外部副本删除。应用对模型服务、Workflow 回放、日志和备份中的受控副本也须完成清单核查；供应商自身的保留条款尚未核验，本决定不能证明供应商会在 90 天内删除。

素材与成片保持私有，只允许当前有权限的项目成员或获授权管理员读取；事实和成片审核须满足当前管理员及项目权限。GitHub 只接收脱敏研发记录，不保存原始业务媒体、提示词、客户资料或私有地址。

## 发布与费用

- 初始渠道沿用 [ADR 0002](0002-camofox-facebook-personal-profile-mvp1.md) 的受控 Facebook Personal Profile。当前 ProductReady、素材权利、成片媒体检查、Gate 01 和独立逐帖确认均为前置条件；审核通过不会自动发布。
- 使用 `docs/reference/` 原件的既有用途／权利授权继续有效。车间素材只证明画面本身，不能对应具体 SKU，也不能补充认证、性能或产能。新增音乐、配音和品牌资产须有自己的授权证据。
- 沿用 [ADR 0004](0004-mvp1-marketing-video-editing.md)：最多 3 个已有素材、成片不超过 15 秒，AI 只提出可编辑初稿。工程事实、正式报价与交期仍按既有人工门禁。
- `coda` 负责现有获授权服务的 AI 剪辑与渲染用量。合成会消耗已有云服务额度，不能写成免费。外部视频生成保持关闭，首期生成预算为 **0**；新增收费服务、商业许可或提高额度须由负责人先给出明确金额上限再启用。本决定不启用供应商、Remotion 付费能力或扩大现有部署资源。
- 请求沿用当前版本去重及受控处理流程；未知发布结果继续暂停，不能因本次政策确认自动重试。

## 可验证状态与执行缺口

本次代码核查确认：`lib/video/review-write-access.ts` 在写入前核对当前会话、管理员、项目成员及所属关系；`lib/video/preview-delivery.ts` 与 `download-delivery.ts` 提供认证的私有媒体访问；`mvp-policy.ts` 默认拒绝视频生成。既有数据库／浏览器验收验证了审核授权、事实及权利门禁。这些证据不等于真实账号接收成片或发布成功。

**90 天到期机制尚未实现。** `video_generated_asset` 及视频聚合目前没有按此政策执行完整的到期访问阻断、提示词清理和 Blob 清理；临时文件的 `finally` 清理与上传回执过期不等于业务保留期。结构化政策是决定记录，当前运行时不读取它，不能将其标作已生效的自动删除配置。

因此保留期、具名责任和生成预算的业务决定已完成，#122 继续跟踪上述执行缺口及其实际验收；不另建业务流水 Issue。补充实现须覆盖边界时间、读取／发布拒绝、仍被来源证据或其他有效对象引用的素材保护、清理失败恢复及脱敏审计。只有这些执行证据通过，才可称保留政策已落实。M2 的真实成片、平台接收、逐帖发布及入站闭环也继续保留各自状态。
