# ADR 0003：项目画布与角色边界

- 状态：Accepted
- 日期：2026-08-31
- 更新：2026-09-01（项目归属、操作坞与导航保护）

## 背景

第一阶段的业务流程受证据、人工确认和状态机约束。传统 Console 和独立视频 Studio 将工作拆到多个页面，要求业务员先理解模块边界，而不是从一个业务项目继续处理。

## 决策

- 采用“业务员执行、管理员确认”的两类角色。数据库保留 Better Auth 现有的 `user` 与 `admin` 值，界面分别称为业务员与管理员。
- 业务员可录入、生成、修订并提交产品、图文内容、营销视频剪辑和 RFQ；管理员保留全部业务能力，并独占人工确认、团队、Product Agent 模型与渠道控制。
- 所有页面与每一个 Server Action 都基于同一权限契约校验；隐藏导航不是安全边界。
- 应用以项目画布为唯一受保护入口。产品营销项目以产品、内容和视频为节点，Gate 01 审核归入对应业务面板；销售机会项目以 RFQ、产品引用和报价交接为节点，完整性确认归入 RFQ 面板。列表、表单和配置以画布面板呈现，不把审核或所有对象强行节点化。
- 左上只显示项目、保存和审核状态标签。底部操作坞统一承载项目切换、新建项目、跨项目待办、工具与账号以及画布保存；不重复产品、内容、视频和 RFQ 入口。待办只做跨项目汇总，并深链接到所属项目的具体节点和记录。
- 工作区级团队、Passkey、Product Agent 与渠道控制从底部操作坞“工具”打开，不进入项目流程。MVP1 不提供视频生成供应商、任务、重试或预算配置。
- 固定流程节点只表达业务领域入口并保存布局，不保存单条聚合标识。产品允许一个项目拥有、多个项目引用；RFQ 只能由一个销售项目拥有；内容和视频只能由一个营销项目拥有，跨项目使用时复制为新的可变草稿。审核记录跟随业务聚合，不单独关联项目。
- 领域创建、审批／事件、项目关联和审计必须在同一事务内完成。工程事实、审核、报价、交期与发布继续由 Server Action、状态机和人工 Gate 决定。
- 桌面检查器按动态视口限高并内部滚动；移动端使用底部 Drawer。同一时刻只出现一个业务覆盖层。表单或画布存在未保存修改时，切换节点、关闭面板、切换项目、浏览器返回和刷新都必须提示。

## 后果

业务员能从一个项目连续处理工作，管理员能在同一空间执行确认与配置；不会改变产品、内容、报价、交期和渠道的既有门禁。该决策不增加第三类审核员、不新增负责人分配或多工厂隔离，也不把合成视频或 Facebook MVP1 实验表述为真实生产能力。
