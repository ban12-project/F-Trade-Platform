# ADR 0003：控制台任务流与角色边界

- 状态：Accepted
- 日期：2026-08-31

## 背景

第一阶段的业务流程是固定且受证据、人工确认和状态机约束的。原控制台按技术模块暴露 Product Agent、视频 Studio 和模型配置；这要求业务员先理解实现方式，且受邀的 `user` 角色不能完成日常工作。

## 决策

- 采用“业务员执行、管理员确认”的两类角色。数据库保留 Better Auth 现有的 `user` 与 `admin` 值，界面分别称为业务员与管理员。
- 业务员可录入、生成、修订并提交产品、图文内容、视频计划和 RFQ；管理员保留全部业务能力，并独占人工确认、团队、模型与渠道控制。
- 所有页面与每一个 Server Action 都基于同一权限契约校验；隐藏导航不是安全边界。
- 主导航围绕待办、产品资料、营销内容和客户询盘组织。模型与团队设置仅向管理员显示。Product Agent 是产品资料入口中的能力，不是业务员需要先理解的独立工作区。
- 视频默认使用分步故事板：已核验事实、简报、素材权利、镜头、平台、提交确认。无限画布保留为高级视图，继续使用同一 `VideoCanvasDocument` 及既有事实/权利校验。

## 后果

业务员能从统一待办进入下一项工作，管理员能集中处理确认与配置；不会改变产品、内容、报价、交期和渠道的既有门禁。该决策不增加第三类审核员、不新增负责人分配或多工厂隔离，也不把合成视频或 Facebook MVP1 实验表述为真实生产能力。
