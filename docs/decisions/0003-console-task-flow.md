# ADR 0003：项目画布与角色边界

- 状态：Accepted
- 日期：2026-08-31

## 背景

第一阶段的业务流程受证据、人工确认和状态机约束。传统 Console 和独立视频 Studio 将工作拆到多个页面，要求业务员先理解模块边界，而不是从一个业务项目继续处理。

## 决策

- 采用“业务员执行、管理员确认”的两类角色。数据库保留 Better Auth 现有的 `user` 与 `admin` 值，界面分别称为业务员与管理员。
- 业务员可录入、生成、修订并提交产品、图文内容、视频计划和 RFQ；管理员保留全部业务能力，并独占人工确认、团队、模型与渠道控制。
- 所有页面与每一个 Server Action 都基于同一权限契约校验；隐藏导航不是安全边界。
- 应用以项目画布为唯一受保护入口。产品营销项目组织产品、内容、视频和审核；销售机会项目组织 RFQ、产品引用、报价交接和审核。列表、表单和配置以画布面板呈现，不把所有对象强行节点化。
- 画布只保存项目关系与布局，节点引用既有受控聚合；工程事实、审核、报价、交期与发布继续由 Server Action、状态机和人工 Gate 决定。
- 左上仅显示项目、保存和审核状态标签。桌面检查器按动态视口限高并内部滚动；移动端使用底部 Drawer。

## 后果

业务员能从一个项目连续处理工作，管理员能在同一空间执行确认与配置；不会改变产品、内容、报价、交期和渠道的既有门禁。该决策不增加第三类审核员、不新增负责人分配或多工厂隔离，也不把合成视频或 Facebook MVP1 实验表述为真实生产能力。
